# 顾客查询与选择规范

适用于办理业务前的顾客身份选择，不用于顾客管理列表、报表筛选或交易记录检索。

- 查询结果为唯一顾客时直接选中，显示姓名和手机号；多条匹配由用户直接点击结果，不自动猜选，也不再增加“确认选中”步骤。空结果、加载和查询失败分开处理。
- 提供更换和清空。更换保留查询词方便修改；清空同时删除查询词。清除当前顾客时，账户、身份标记、当前顾客业务草稿及未展示的旧结果必须失效，不沿用上一位顾客的数量、卡片、二维码或确认状态。
- 查询和选中不代表身份所有权验证、付款授权、实际收款、开户、领卡或核销。保留最终业务确认和原有权限/幂等边界。钱包查询可读取已有账户，但缺失账户需要明确的“开通本店钱包”操作，不在唯一结果自动选择时发出开户命令。
- 更换门店、编辑查询、清空、离开组件或切换任务后，旧响应不得重新填入顾客或结果。采用拥有业务上下文的请求版本检查，不只比较顾客ID。
- 复用模块已有查询接口及租户/门店权限；不要另建顾客目录或跨租户搜索。外观沿用所属模块，语义统一不意味着复制同一种页面布局。

当前实现：卡券 CardOperations；钱包/积分 WalletStaffCustomerPicker 和 WalletPhoneCustomerPicker；酒存 useMerchantStorage 与 StorageCustomerPicker。预订、排队和直接入座的 StaffGuestContactLookup 本来已按完整手机号自动回填，无重复选择步骤，继续保留已有编辑方式。新增产品应遵循以上语义并覆盖唯一、多条、无结果、更换/清空、迟到响应、门店切换及无自动业务写入测试。
