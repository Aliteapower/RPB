# RPB 同类页面布局一致性指南

适用范围：D:/RPB 内已有管理页、业务工作台、员工资料页和设置页的 UI 调整。新增页面也应先寻找所属模块的现有基准。本文源于 2026-10-31 员工考勤设置及员工编辑页的实际登录验收，用来避免局部优化后出现宽度、对齐和操作样式不一致。

**先复用所属模块的页面骨架和公共样式，再优化业务内容。不能只看单个页面是否美观，必须与相邻页面放在一起验收。**

## 1. 本次问题及可复用结论

| 问题 | 原因 | 后续处理原则 |
| --- | --- | --- |
| 排班、考勤设置和员工编辑页面宽窄不一 | 公共内容区约 1072px，编辑页私设 860px 并居中，考勤页又套了 760px 的窄表单类 | 外层使用同一模块的公共容器；不要在业务页重新声明无业务依据的最大宽度和居中规则 |
| 编辑页像另一套页面 | 没有复用公共白底面板，保存栏另加边框、圆角和阴影 | 复用公共面板、标题、按钮和操作区；页面专属样式只处理确有需要的业务布局 |
| 保存栏盖住下方内容 | 局部新增 sticky 悬浮与层级 | 默认沿用普通流式操作区；确需悬浮时再核对遮挡、留位、窄屏和键盘焦点 |
| 构建通过，但用户仍发现明显视觉差异 | 此前缺少登录后的相邻页面比较 | 构建和组件测试之外，必须查看真实登录页面、实际 CSS 尺寸与截图 |

1072、860、760 是本次环境下的诊断数值，**不要将 1072px 再硬编码到其他页面**。正确做法是继承公共容器，让尺寸随模块布局和视口变化。

## 2. 修改前先确定参照页面

1. 明确项目、模块、入口路由和用户角色，不将另一个项目的样式或规则套进来。
2. 选择同模块已正常使用的相邻页面作为参照，例如员工模块的排班页、员工列表页；不要只参照孤立截图。
3. 阅读模块 Layout、公共 CSS、公共页头及目标页的 scoped CSS，确认宽度由哪一层负责。
4. 记录修改前的外层宽度、左右边界、面板留白、标题、按钮及保存区，保留问题截图。
5. 沿用用户已确定的业务分区方式。考勤页的功能切换和员工编辑页的单页折叠可以不同，公共外观仍应一致。

不要为了“统一”重构其他正常页面，也不要把所有表单一律改宽或改窄。

## 3. 员工模块的样式来源与使用边界

以下是当前员工模块的实现入口；其他产品线应查找自己的对应实现，不直接搬用 `wf-*`。

| 职责 | 来源 / 约定 |
| --- | --- |
| 模块外层、公共导航与路由内容 | [WorkforceLayout.vue](../../src/modules/workforce/WorkforceLayout.vue) 中的 `.workforce-page` |
| 面板、字体、留白、网格、按钮及响应式规则 | [workforce.css](../../src/modules/workforce/workforce.css) |
| 产品页头、返回、门店及语言操作 | [ProductPageHeader.vue](../../src/components/common/ProductPageHeader.vue) |
| 普通业务面板 | `.wf-panel`，继承模块可用宽度 |
| 有意采用窄宽度的独立表单 | `.wf-form-panel`；它当前有 760px 上限，不是所有含输入框的页面都应该套用 |
| 表单网格 | `.wf-grid`；桌面多列、窄屏单列，保留 `minmax(0,1fr)` 的收缩能力 |
| 常规保存与取消区 | `.wf-form-actions`；沿用按钮主次关系和分隔线 |
| 宽表格 | `.wf-table-wrap`；在表格区域内横向滚动，不撑宽整个页面 |
| 员工业务折叠区域 | [EmployeeTaskSection.vue](../../src/modules/workforce/components/EmployeeTaskSection.vue)；按需展开，保留已输入内容 |

当前公共样式快照：模块外层最大宽度 1120px，桌面横向 padding 24px；面板 padding 为 16px/18px；600px 以下面板 padding 为 14px/12px。以后以公共 CSS 的实际定义为准，不在页面中复制这些数值维护第二套规则。

同类工作台或资料编辑页可以沿用下面的结构，具体组件仍按现有业务组织：

```vue
<section class="wf-panel employee-editor">
  <header class="wf-toolbar">...</header>
  <!-- 业务内容、已有表单或折叠区域 -->
  <footer class="wf-form-actions">...</footer>
</section>
```

需要避免的局部覆盖：无依据地新增 `max-width:860px; margin:0 auto`、给综合页面误套 `.wf-form-panel`、重新定义另一套面板底色/阴影/按钮、用负边距或固定宽度勉强对齐。

如果业务确实需要独立窄表单、打印版或其他布局，复用项目中同类型的既有模式，并说明业务理由；不要把本指南解释为所有页面结构和尺寸必须完全相同。

## 4. 聚焦业务，同时保留原有操作边界

- 首屏突出用户当前要办理的事；辅助资料和历史按用户要求采用切换、折叠或独立入口，避免全部堆叠。
- 显示员工姓名、岗位、审批人姓名等业务含义，不用 UUID 代替正常业务名称。缺失名称应有明确文案，不随意回退显示内部 ID。
- 当前执行、待生效、已结束必须明确；可以合并展示等价历史，但不能删除真实记录或改写历史快照。
- 明确每个保存按钮负责的内容。员工资料、账号密码、证件和薪资的独立保存边界不能因排版调整而混在一起。
- 折叠和切换不能丢失草稿；首次按需加载的区域再次展开时，不应重置未保存输入。
- 必填字段不能因折叠变得无法定位。校验失败时应展开对应区域，并保留浏览器正常聚焦行为。
- 优化外观不改变权限、账号启停、审批规则、幂等重试或业务计算；已有无关工作区改动继续保留。

## 5. 桌面与手机验收方法

### 桌面

- 在相同实际 CSS 视口、缩放和滚动条条件下，对照基准页与目标页。
- 同类页面的外层面板与模块导航左右对齐，公共留白、标题层级、输入框和主次按钮一致。
- 检查默认状态，以及任职、账号、薪资、证件、地址历史等展开后的布局；不要只看首屏。
- 检查保存区不遮挡输入、折叠标题或其他操作，长文案和异步加载后不重叠。

### 手机尺寸与语言

- 至少检查约 390px 和 320px 的实际 CSS 视口；表单应合理变为单列，操作按钮可换行。
- 检查所有功能切换、展开区域、长姓名、长说明及中英文，不仅缩小浏览器看一张截图。
- 页面不出现意外横向滚动；宽表格可在自身区域滚动。公共导航按既有设计横向滚动，不等于整页溢出。
- 展开异步区域后确认内容和展开状态，再继续下一步，避免把加载中的布局当作最终结果。
- 有条件时补充实体手机；只有模拟视口证据时，明确写“手机视口验收”，不声称完成手机、微信或 GPS 实测。

### 用真实 DOM 核对，而不是凭截图猜尺寸

通过浏览器工具允许的只读 DOM 检查读取：

- `window.innerWidth / innerHeight`：实际 CSS 视口。
- `document.documentElement.clientWidth / scrollWidth`：页面可用宽度与横向溢出。
- `getBoundingClientRect()`：模块导航、外层面板及操作区的边界和宽度。
- `getComputedStyle()`：实际 padding、网格列数、position 和 max-width。

同类面板和导航的几何边界应基本一致，允许像素舍入误差；无设计外横向内容时，页面 `scrollWidth` 不应超过 `clientWidth`。但尺寸断言不能代替截图目视检查，仍需检查遮挡、裁切、可读性和点击目标。

浏览器缩放、设备像素比、视口工具参数和截图物理像素可能不同。本次工具参数对应的实际 CSS 宽度是 1441、391 和 321px；记录实际观测值，不把设置参数直接写成验收结论。内容较短时滚动条消失也会改变 `clientWidth`，比较时应考虑这一点。

## 6. 验证和交付要求

修改完成前逐项确认：

- [ ] 已选同模块基准页，并检查 Layout、公共 CSS 和目标页覆盖规则。
- [ ] 外层容器、面板、标题、表单和操作区复用已有样式，新增差异有业务依据。
- [ ] 业务分区遵循用户要求，保存、权限、草稿及历史语义未被排版修改破坏。
- [ ] 已按影响范围运行构建和相关测试；纯样式低风险修改不为形式新增镜像测试。
- [ ] 旧测试需要切换功能页或展开区域时，更新真实操作步骤，保留原业务断言，不只删除失败断言。
- [ ] 已登录检查桌面、两档手机视口、关键展开状态及中英文；没有登录或浏览器受阻时明确说明未完成部分。
- [ ] 已保存截图及关键尺寸证据；含员工、账号、薪资或证件资料的截图保留在本地私有验收目录，不提交公开 Git。
- [ ] 汇报实际改动、验证和剩余限制，不将构建成功、匿名 HTTP 或资源哈希检查当作登录后的视觉验收。

如需发布，继续遵循任务已有授权及项目发布流程：只提交本次文件，用干净候选构建，保留无关改动。纯前端修复无需因此重启后端或部署数据库；仍须核对前端版本、实际资源、回退点和发布后页面。实现本身不自动授予生产发布权限。
