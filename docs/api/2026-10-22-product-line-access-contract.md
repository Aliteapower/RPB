# 产品入口与单店到期控制修复契约

状态：用户已授权本地实现，暂不发布。范围为既有产品接入修复，不新增付费产品、租户或价格，不迁移/删除已有品牌数据。

## API 与兼容性

- 产品创建/编辑 API 保持原 DTO 和平台权限。默认入口统一来自代码随包发布的 `product-line-entries.json`，包含空入口、员工首页、PayNow 和每日营业记录页面；站外或未实现路由仍返回既有 `REQUEST_INVALID`。
- 产品运行时入口权限由同一受控文件声明，不从 `platform_apps.config_json` 接受权限升级。未注册产品可登记目录，但不会获得运行时入口。
- App Gate 接口拒绝与 `visible-apps` 使用相同门店商业状态：已有门店计费明细的产品必须存在目标门店有效明细；到期时（结束时间 <= 当前时间）接口返回 403 `STORE_APP_EXPIRED`，菜单隐藏；兄弟门店不受影响。
- 暂停、取消或无目标门店明细返回 403 `STORE_APP_NOT_ENABLED`。先保持既有平台/租户总开关校验，再叠加门店条件；操作开关不能绕过商业到期。
- 历史无门店计费明细授权及 `legacy_grant` 保持原租户授权语义。已经按店计费的订阅不允许因目标店缺明细而回落永久授权。
- 本次只增加单店结束时间约束，不开启未来生效时间的新语义：现有续费把 `current_period_start` 更新为下一周期起点，不能直接据此阻断提前续费后的当前使用。
- 门店结束时间为空时回退订阅结束时间；两者都空表示既有不设结束时间。数据库查询以租户、门店、产品及订阅关系限定，不依赖计费应用服务。
- actor 租户与请求租户不一致时拒绝，不允许拿其他租户上下文评估。门店菜单仍检查可见开关、账号动作权限和门店访问权。

## 共享资料

每日营业记录继续调用 `TenantAdminProfileService`，门店名称使用统一门店资料，Logo 仅使用当前租户媒体引用。旧品牌 JSON 保留供显式迁移，不作为当前展示的备用资料源；清除公共 Logo 后不能恢复旧 Logo。产品私有英文名不再冒充门店统一名称；缺公共翻译时保留产品默认副标题。原品牌导入流程仍可显式接管旧 Logo，不在读取时写入。

## 测试清单

1. 注册表路由与前端实际路由对应；入口权限与现有角色能力一致，未知产品/伪造 JSON 不可授予入口。
2. 创建/编辑独立产品入口及只改名称；拒绝任意路径。
3. 到期、恰好到期、未来到期、暂停、取消、缺门店明细、永久授权；接口与可见列表一致。
4. 同租户 A 店到期而 B 店可用；续费后 A 店恢复且 B 店明细不变；跨租户拒绝。
5. PostgreSQL 实际 SQL 验证作用域、关联及历史兼容，使用本工作区指针数据库和新建隔离测试 schema。
6. 公共名称/Logo 更新及清除立即读取新状态；旧 JSON 不被修改，不能越权读取旧/他人媒体；业务设置不能反写品牌。
7. 相关 App Gate、计费、租户资料及产品回归，前端类型检查与构建。

## 数据库与模块审查

无需迁移。App Gate 增加只读商业有效期投影，查询现有订阅和门店明细表，不导入 `platformbilling` 类或改变业务服务的依赖方向。已有租户/产品唯一键和门店明细索引可支持查找；菜单按当前租户门店一次批量读取，不逐产品查询。到期只拒绝访问，不改门店配置或历史业务数据；续费沿用现有事务与同步。
