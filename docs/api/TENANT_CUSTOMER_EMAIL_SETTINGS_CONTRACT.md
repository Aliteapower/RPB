# 租户共享顾客邮件配置

## 业务及权限

同一租户的门店与使用顾客账号的产品线共用一份 SMTP 配置。首次保存即建立租户配置；关闭产品或邮件开关不删除配置。普通员工、顾客、跨租户/未分配门店不能读取或修改配置。

`GET/PUT /api/v1/stores/{storeId}/tenant-admin/customer-auth/email-settings` 要求租户管理员、`tenant.admin.manage`、本人门店范围、真实有效门店，以及产品注册目录中至少一条拥有顾客入口的产品通过本店 AppGate 商业校验。无需开通预订排队；不自动开通其他产品或恢复门店开关。旧 `/tenant-admin/public-booking/customer-auth/email-settings` 作为相同策略的兼容别名。其他预订和 OAuth 接口维持预订产品边界。

请求沿用原 SMTP DTO；空密码保留已有密码。响应沿用原脱敏 DTO，不返回密码，新增 `configurationScope`：`tenant` 为租户共用，`legacy_store` 为旧门店配置待确认统一，`unconfigured` 为首次配置。保存是同一租户单行 upsert，并在同一事务内记录操作者与开关状态的租户级审计，不记录 SMTP 地址、账号或密码，不发测试邮件。重复保存不会创建重复配置；并发更新沿用最后保存生效语义。

错误沿用 tenant-admin 体系：未登录 401；角色/权限不足或产品均不可用 403 forbidden；门店归属无效 403 store_scope_mismatch；参数无效 400 request_invalid；数据库错误 500 persistence_error。

## 数据兼容

新增 tenant_customer_email_settings，以 tenant_id 唯一关联租户，含既有 SMTP 字段、时间戳和版本；不改写旧 store_customer_email_settings。迁移只将有完整发信地址和主机、且租户内所有有意义旧配置完全相同的配置提升为共享配置（包含原开关状态）。冲突租户保留旧门店回退，管理员在共享页明确保存后统一；不随机选择冲突凭证。未配置租户保持关闭。租户行存在时优先使用，即使已关闭也不能回退旧配置。

所有既有邮件登录、验证、找回密码均通过原 repository port 读取共享配置；不复制 SMTP 到各产品，不改变顾客账号、验证码、频控或订阅。多门店首次保存后自动共用；历史旧表保留。OAuth 不在本次共享改造范围。

## 验证清单

- 存酒/钱包独立开通时可读取、首次保存、关闭及重新启用；预订未开通也可用。
- 有效产品关闭/到期全部拒绝，恢复后可用；配置保留。
- 未登录、员工、缺少权限、跨门店/租户拒绝，读取响应不泄露密码。
- 跨门店及跨产品共用，空密码保留，关闭不回退，重复首次保存唯一。
- 旧单一配置迁移、冲突保留、空配置不误迁移、外键与租户隔离。
- 前端首次配置、已配置状态、旧配置提示、错误禁用提交、切店晚响应、重复提交、中英文。
