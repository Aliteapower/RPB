# 顾客取酒码扫码即核销（2026-10-26）

POST `/api/v1/stores/{storeId}/wine-storage/scan-deliver`

请求 `{code: 'WS....', idempotencyKey}`；仅商户身份、wine_storage.deliver、本租户/门店。仅接受 origin=customer 的取酒码（顾客生成时已明确授权酒品及瓶数）。扫码即代表办理本次取酒，直接在同一事务调用原交付领域规则：锁领取意图和库存、检查授权/取消/期限/归属/数量、整批扣减并置 completed，返回 Intent（code=null）。失败整批回滚，沿用 STORAGE_INVALID400 / NOT_FOUND404 / FORBIDDEN403 / CONFLICT409 / BATCH_CONFLICT409。

旧 `/scan` 保持只读、旧 `/intents/{id}/deliver` 保持原行为；商户出码由顾客扫描授权的流程不自动扣减。扫码页面提前明确提示“扫码即核销”，识别后不再显示额外确认按钮。

幂等按租户/门店/操作人/staff/scan.deliver/key和完整请求。原操作响应丢失时必须用同一键重放，即使码已完成或之后过期，返回原成功结果；新键再次扫已完成码返回409，禁止重复扣减。并发不同收银员/键通过原意图行锁只能成功一次。借助原命令响应恢复结果，不在照片、日志或流水备注写明文扫码令牌。

顾客端显示取酒码期间定时及返回页面时刷新状态，完成后隐藏二维码和取消按钮，显示已核销/取酒完成；失效是服务端状态控制，截图也无法二次使用。二维码仍按原5分钟有效，库存及酒品期限不因扫码改变。

无需迁移、无需新增权限。测试：成功一次扣、同键断网重放、新键重复、并发、防跨门店/租户/错码、商户来源码拒绝、取消/超时/库存变化整批失败，原商户出码流程保留，顾客QR状态刷新与已完成不显示QR。
