# 叫号屏个人资料输出约束

接口：GET `/api/v1/stores/{storeId}/queue-display/state`。

叫号屏供现场多人观看；即使操作者已登录，返回内容也应最小化。现有角色、门店权限、App Gate 和租户查询边界不变。

`currentCall.customerDisplayName`、`waiting.preview[].customerDisplayName` 均在后端响应映射时脱敏：正常姓名仅保留第一个 Unicode 码点并附 `***`；单字符姓名、包含数字或 `@` 的称呼完全隐藏为 `***`；缺失称呼显示 `顾客`。票号、人数及叫号状态保持不变。不会修改顾客或预约原始资料，也不影响内部授权联系顾客的接口。

两处排队读取日志只输出稳定事件名和异常类名，不输出异常 message、toString、SQL 参数或堆栈中的数据。

验证清单：当前叫号及候位均脱敏；中文、英文、补充平面字符、电话型称呼、电邮型称呼、单字符和空值；序列化响应不含原值；原始资料保持；权限拒绝、门店隔离及既有 App Gate 回归；含个人资料的数据库异常不进入日志。

这些措施属于资料暴露最小化，不等于匿名化证明或完整 PDPA 合规认证。登录凭据规则、保留期限、顾客权利及生产基础设施另行评估。
