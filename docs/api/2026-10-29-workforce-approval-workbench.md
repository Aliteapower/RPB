# 工时核准工作台（实现契约）

复用原核准、异常判定、打卡事实及计薪快照。新增工作台与批量编排，不自动核准、不直接改打卡或工资。保留单条API兼容。

- GET `/approval-board?from&to&category&positionId&search&limit&offset`：当前授权门店，普通员工仅本人。范围最多31天，默认前一天；分页最多100条。分类all/normal/manager/exception/waiting/stale/current，返回筛选总数、所有分类数量、每天进度、岗位选项及核准权限说明。扫描最多50000条排班（扫描后排除已取消记录），超限明确拒绝，替代旧1000条限制；来源、最新核准分块批量读取，避免逐条读取全历史。工时汇总也改为分块读取，超过50000条明确拒绝，不静默截断。
- 每行包括原ApprovalRow、实际进出时间、分类、canReview及reviewBlock。正常批量候选必须无原核准、无阻断问题、无待判定/异常发现（已批准请假LEAVE除外）。已结束完整整班请假可以作为正常候选；未结束、缺卡、待审请假/补卡/销假等不能进入批量候选。已核准后来源变化只能重新人工检查。
- PUT `/approval-board/preview`：`{filter:{from,to,positionId,search},all:boolean,ids:UUID[],excluded:UUID[]}`，跨页全选由服务器重新筛选正常且有权限记录，返回固定候选ID、版本、来源指纹及合计，前端分页展示预览。预览后修改筛选/选择须重新预览。
- PUT `/approval-board/commit`：`{note,items:[{scheduleId,expectedVersion,sourceFingerprint}]}`，每次最多100项，说明必填、最长500字。前端按100条分块提交；各项独立事务调用原核准服务，正常条目成功，业务冲突返回该项错误，不阻断其他条目。服务器重新核对正常资格、权限、版本和来源。重复相同请求沿用原核准幂等，不重复累计。响应未知冻结原块，原样重试后继续余下块。
- GET `/approval-readiness?companyId&month=YYYY-MM`：按原工资公司权限检查所有涉及门店，仅返回公司/月及门店核准计数、有效工时、待处理数量，不返回原始打卡明细。显示为“本月工时核准检查”，只代表该月排班工时核准进度；正式工资确认仍沿用原配置、跨期加班来源、来源变更/阻断检查和冻结快照。

权限：经理只处理已授权门店普通员工，禁止本人核准。员工关联账号具有store_manager/tenant_admin角色，或任一员工管理授权时视为管理人员，其工时只能由现有headOffice管理员核准（仍禁止自审）。该限制同时作用于旧单条及新批量接口；详情返回canReview/reviewBlock，避免仅前端隐藏。旧历史核准不改写，新规则约束后续核准操作。

错误：401未认证、403越权/经理须管理员核准、400非法范围/超限、409来源或版本冲突/业务阻断。沿用no-store、精确方法路径及同源写保护。每次批量核准仍保存原逐条审计与快照。

验证：正常批量、异常/待审/未结束拒绝、来源变更、逐项失败独立回滚、重放、跨页全选与排除、1000条以上分页、批量来源与原来源指纹一致、管理员/经理/本人/跨店/跨租户/AppGate、工资权限与旧工资阻断、前端行内处理和未知响应恢复。无新增迁移；工作区旧改动保留，只有本地验证，不部署。
