# 餐饮跨日班次与营业日期契约

沿用/api/v1/stores/{storeId}/workforce/shifts及原排班接口、权限、乐观版本和门店/租户隔离。

ShiftWrite/Shift在原字段后增加可选startNextDay:boolean。缺省、null、false均为营业日期当天开始，保存时false归一为null并省略JSON字段，以保持旧快照结构；true表示实际开始日为排班workDate+1。原nextDay表示相对实际开始日的次日结束。所有班次实际跨度仍须大于0且不超过24小时，DST歧义/不存在时间继续拒绝。

| workDate | 开始/结束 | startNextDay | nextDay | 实际时段 | 归属 |
| --- | --- | --- | --- | --- | --- |
| 2026-10-31 | 11:00/23:00 | 省略 | false | 10-31 11:00–23:00 | 10-31 |
| 2026-10-31 | 16:00/00:00 | 省略 | true | 10-31 16:00–11-01 00:00（24:00） | 10-31 |
| 2026-10-31 | 23:00/06:00 | 省略 | true | 10-31 23:00–11-01 06:00 | 10-31 |
| 2026-10-31 | 01:00/06:00 | true | false | 11-01 01:00–06:00 | 10-31 |
| 2026-10-31 | 23:00/06:00 | true | true | 11-01 23:00–11-02 06:00 | 10-31 |

24:00为展示约定，传输/存储使用00:00及nextDay=true。班次休息偏移仍相对实际开始时刻。工时以真实Instant计算，营业日期用于排班、统计和计薪归属；不因自然日翻页重复支付。跨门店排班冲突按实际起止时间比较。

新属性存入既有workforce_shifts.snapshot及新排班shift_snapshot，不新增列、不重写旧排班、打卡或工资。编辑班次不反向改变旧快照；恢复已取消排班仍使用原时间快照。复制/批量调班按目标班次及目标营业日期重新换算，预览与提交保持相同逻辑。
