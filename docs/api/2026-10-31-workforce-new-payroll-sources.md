# 新版工资来源与合同计发

本契约用于开发重建，不提供旧工资快照、旧SourceRef或旧工资API兼容。旧工资按已授权清单在替换窗口清理；员工、打卡、请假及法定政策不在删除范围。

## 有效个人方案

继续通过现有个人薪资方案及经济变更审批端点保存 `rule.generation`，新增 `mode=contract` 和 `contractTerms`：

- `employmentProration`：`full` 明确约定有效雇佣月按全额；`working_days` 按当月工作日及有效雇佣期间折算。
- `unpaidLeaveTreatment`：`no_deduction` 明确不扣；`deduct` 按有效工作安排净无薪假时间折算。
- `overtimeTreatment`：`included` / `separate` / `not_applicable`，必须明确。`separate`只消费批准的额外工作申报单位，使用本人约定单价与倍率；不从打卡或排班差额生成合同加班。

合同模式关闭基于出勤日/周阈值的自动加班。月薪全额且不扣无薪假的明确合同可以没有工作周；其他合同计薪需有有效工作日及日标准单位。日薪/时薪按合同单位计发，这些单位不显示为实打或核准出勤。缺少必要条款、单位、雇佣期间或来源存在未决申请时阻断受影响计算，不能默认全额或零工资。

条款属于个人经济待遇，沿用模板采用、经济变更审批及生效治理；不能通过考勤设置接口修改金额或条款。新模型的审核、确认、发布、付款及纠错保持独立。

## 来源证据

新版来源使用 `sourceId / sourceVersion / sourceType`，而不是强制使用排班ID/人工核准版本。类型为actual/arrangement/contract/free，保留来源指纹、方式及源版本；实际工时允许为空。

有效每日来源来自统一考勤服务：system_valid/human_valid可进入普通计薪；合同/free使用not_applicable和相应合同/自由单位，不能要求补出勤。pending/stale及未决申请不视为有效；未来及非雇佣期间不提前计出勤。工资捕获纳入政策、每日来源及合同条款指纹，重算和正式确认继续校验。

逐日加班共用 `DailyWorkAllocation.allocate`，先合并同日跨店工时再应用日周阈值，带薪假单独保留；前月周上下文只消耗阈值，不重复支付。合同另计加班使用明确批准申报，独立于该出勤阈值算法。

权限沿用员工考勤、工资公司及原本人限制；普通月表仅返回有权查看的时数及状态，不返回单价、金额、合同附件或GPS。不同发薪公司不合并计薪。

## 无考勤依赖条款

自由免考勤固定工资不受仅供记录的请假/打卡待审影响。合同明确不扣无薪假且加班已包含或不适用时，待遇只引用有效合同、雇佣期间和政策单位；信息性请假净时长未知不要求补打卡或工时核准，工资指纹不引用无关打卡/请假状态。需扣无薪假或另计加班的合同则必须具备对应有效净单位，相关未决事项继续阻断。工时readiness对合同/自由显示无需工时核准，不代替合同条款或金额准备检查。
