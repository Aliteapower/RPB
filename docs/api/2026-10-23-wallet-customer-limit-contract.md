# 顾客自主设置个人码支付上限

本契约取代个人付款契约中的管理员限额配置。顾客输入SGD单笔免确认金额并明确授权一次，之后刷新个人码、付款成功再出码均沿用持久授权，不逐笔或每次打开页面索取同意。超限仍确认原账单。仅顾客本人可修改/撤销自己的授权，商户没有代配置能力。

复用 GET/POST `/api/v1/public/stores/{storeId}/wallet/personal-payment-consent`。POST仍使用`policyVersion,limitCents,accepted,idempotencyKey`，其中历史字段`policyVersion`改为**此顾客、此钱包计划授权记录的乐观版本**，不再关联管理员策略。GET返回当前个人版本（无记录0）、个人已保存上限与付款启用状态。成功修改版本加1；旧版本409 `WALLET_POLICY_STALE`，需重新加载自己的设置，不能静默覆盖。重复相同幂等键返回原成功响应，异参冲突。

accepted=true必须输入1..9999999999999整数分；不自动填默认金额、不默认无限额。accepted=false可空上限。旧已明确授权的金额保留，不自动扩大。复用原consents表和policy_version字段，无新迁移、无历史账本重写；旧管理员policy表只保留历史数据，停止读写业务使用。退役员工personal-payment-policy GET/PUT及可见配置区。

每次修改上限或关闭付款，持锁使该顾客已有二维码付款快照失效（身份识别不受影响），出码端获取新码。扣款同时校验当前个人授权和码上快照；取两者较小上限，一码至多支付一笔。授权持久有效直至本人变更/关闭或原身份、账户等规则使其不可用。不改动资金、退款、营销、积分或交易查询。

验证：无管理员配置也能启用；一次授权连续多个新码支付；顾客独立限额/权限隔离；增减限额/关闭再启用不能复活旧码；并发设置版本冲突；空/零/小数分/越界拒绝；超限仍原单确认；原并发、幂等、租户/门店校验不回归。前端展示自填上限、金额变化取消勾选、保存后沿用、不自动授权。
