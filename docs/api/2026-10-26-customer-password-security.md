# 顾客首次改密、电邮找回及同意规则一致性

## 设计与计划

范围：复用 customer-auth、现有租户/门店解析和 SMTP 配置；不向钱包、卡或寄存模块复制认证逻辑，不发布生产。

1. 最新授权采用[到店一次性激活](2026-10-26-customer-in-person-activation.md)，取代早先手机号后六位登录后强制改密的方案。无凭据、仍需改密或六位凭据均不能密码登录；旧受限会话不能调用改密。没有已验证电邮的未激活顾客到店核实，由有顾客管理权限的员工发码，顾客凭码设置密码后自行登录。新密码至少 8 字符、最多 72 UTF-8 字节。已有自设密码及已验证电邮找回保留。
2. 在普通已登录状态提供电邮绑定验证码及确认；只信任已经验证的认证账户电邮，不信任顾客资料中手填的 email。首次绑定不覆盖其他顾客账户，已有不同认证电邮不通过此流程更换。未绑定者可正常使用，但忘记密码需联系门店核实，不能退回初始密码。
3. 找回提交门店、手机号及已验证电邮。发送接口对匹配、不匹配、未登记返回相同成功结构，不返回验证码、目标电邮或顾客存在性。有效请求向匹配电邮发 10 分钟、单次使用验证码。绑定与找回验证码按用途、租户、门店、顾客、电邮及认证账户隔离，哈希保存，五次失败锁定，重发使同作用域旧码失效；独立事务限流不因失败回滚。
4. 找回确认校验验证码并加锁；设置新密码、消费验证码、撤销所有旧会话及同顾客其余找回/绑定验证码原子完成；不自动登录。普通改密也撤销同租户顾客全部安全验证码，避免旧码改回密码。成功后回到登录页。
5. 登记同意保持当前明确口径（包含营销推送同意或钱包扣款授权），服务端版本升为 `customer-profile-v2`，更新活跃合约与测试，不改历史快照，不把登记同意替代具体扣款校验。

## API

基址 `/api/v1/public/customer-auth`，JSON POST 均要求 `X-RPB-Customer-Auth: 1` 且拒绝 cross-site/same-site Fetch Metadata。现有客户端同步更新；范围只覆盖密码登录/改密及新安全端点。

- `password-login` 原请求不变；只有已设密且不再需要初始改密的凭据可登录，其他情况统一 invalid_credentials，不创建受限会话。响应保留 `passwordChangeRequired` 供旧会话兼容，成功新登录为 false。
- `password-change` 原请求不变，仅普通顾客会话及实际自设密码可调用；成功返回普通会话并撤销旧码。旧受限会话不能以改密激活。
- `recovery-email-code`：`{storeId,email}`，普通顾客会话，发送绑定码。
- `recovery-email-confirm`：`{storeId,email,code}`，普通顾客会话，确认绑定，返回 `{success:true}`。
- `password-reset-code`：`{storeId,phoneE164,email}`，匿名可调用；统一 `{success:true}`。
- `password-reset`：`{storeId,phoneE164,email,code,newPassword}`，成功 `{success:true}`；匹配失败统一 `code_mismatch`，过期/重放同样拒绝，不透露账户状态。
- `me` 识别受限会话，返回标志以便刷新后继续改密。

错误沿用 request_invalid/unauthenticated/code_mismatch/rate_limited/email_channel_not_configured/email_delivery_failed/persistence_error 及既有状态映射。所有新响应 private,no-store；发送接口不暴露 devCode。邮箱绑定冲突返回 request_invalid，不泄露他人身份。

## 数据与兼容

V082 增加会话和凭据的强制改密标志、带复合 tenant/store/customer/account FK 的用途验证码表。历史凭据版本 0 是 V058 初始凭据写入，显式改密会使版本递增，因此按 version=0 标记尚需改密，换手机号不会清除此标记；若历史自定义密码通过外部方式直接以版本 0 写入，也会保守要求改密。一次性撤销已有具备密码凭据顾客的活动会话，避免旧版初始密码普通会话绕过；不改密码、业务资料及余额。通过原有改密流程保存的历史非初始密码再次登录仍为普通会话。邮箱/OAuth 的验证登录行为不改变；其旧会话若属于上述顾客也需要重新登录一次。

上线需要数据库、后端、前端配套；此轮仅本地验证。回滚应用不会自动恢复已撤销会话；保留迁移与验证码审计资料，不逆向恢复旧凭据。
