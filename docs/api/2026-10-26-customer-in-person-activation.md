# 到店核实后一次性激活

## 规格与实现计划

用户选择无短信、无已验证电邮时到店由有权限员工发码。首次密码不再从手机号推导。customer-auth 拥有激活及凭据，顾客管理复用发码组件；钱包只提供现有管理入口。

- 发码权限沿用现有共享顾客管理：tenant_admin + tenant.admin.manage + 已授权门店；平台/其他租户及普通店员不得发码。无需钱包订阅，以便产品停用时仍能管理顾客身份。
- 员工必须提交 `identityConfirmed:true`，明确记录已当面核实，不能用手填电话或电邮自动推定。活跃、拥有手机号、尚未设密且没有已验证认证电邮的顾客可以发码；已有自设密码不能被发码覆盖，已验证电邮使用现有找回。
- 激活码随机 12 位（去歧义大写字符及数字），10 分钟有效，5 次错误锁定；只在本次发码响应显示明文。数据库仅保存盐化哈希；不进入日志、审计正文、浏览器持久化或 URL。员工应当面交付；页面离开/切换顾客或门店清除显示。
- 发码记录租户、门店、顾客、发码员工、当面确认时间、创建/更新时间。重发撤销该租户顾客所有旧激活码；网络结果不确定时显式重发，不提供查询明文或自动重试。
- 顾客提交门店、手机号、激活码及新密码。验证时锁定顾客及码，错误计数保留；跨租户/门店/顾客、过期、重放、锁定、已激活一律拒绝。设置密码、标记已设密、消费所有激活码、撤销旧会话及安全码、审计同事务完成。成功不自动登录。
- 所有手机号后六位登录及改密后门关闭；没有自设密码/仍需改密的凭据登录统一 invalid_credentials。不创建顾客、凭据或会话。普通已设密登录、电邮找回、OAuth/已验证电邮登录保留。

## API

- POST `/api/v1/stores/{storeId}/tenant-admin/customers/{customerId}/activation-codes`，`{identityConfirmed:true}`；成功 `{success:true,code,expiresAt}`，private,no-store/no-referrer。认证401、权限或范围403；不存在/不符合/未确认400；限流429；持久化500，均使用 customer-auth 的稳定 error 响应。此入口重发会换码，不是可重放的明文读取接口。
- POST `/api/v1/public/customer-auth/activate`，`{storeId,phoneE164,code,newPassword}`；成功 `{success:true}` 无 Cookie；失败 code_mismatch 或 request_invalid、限流429。门店由服务器解析租户，不接受 customerId/tenantId。前端附 `X-RPB-Customer-Auth:1`，服务器拒绝跨站写入。发码入口同样受该请求头与来源保护。

## 数据库与发布

V083 增加 customer_activation_codes，租户/门店/顾客及发码员工复合 FK，失败次数/到期/哈希约束和查找索引；撤销旧受限或仍有初始凭据顾客的活动会话，保留原密码哈希和历史证据。V082 不重写。上线必须配套新迁移、后端和前端，旧客户端需刷新；本轮没有生产发布授权。
