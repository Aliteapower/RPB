# 酒水寄存 / 存酒卡（2026-10-25）

本次仅开发及本地验证，不发布生产。保留任务开始前的钱包组件及验收资料改动。

## 边界与决策

采用单体内 `winestorage` 模块及 `src/modules/wine-storage`，独立拥有申请、收存、照片、规则版本、领取意图、流水及幂等命令。钱包只提供链接和扫码识别适配。身份来自 customerauth / CurrentActor；商户、门店来自共享目录查询；产品通过 catalog 应用边界访问。不接触资金、积分、卡次数及可售库存。

不选择将寄存放进钱包账户或商品库存：两者生命周期、计量和权限均不同。产品保留租户共享、门店投放；仅建档使用 NULL 价格，storage 唯一渠道，销售前须完成现有目录销售校验。顾客建议在确认前仅保存于商户申请，不对外列为产品。

## 状态、时间与并发

申请 pending -> stored / rejected / cancelled。申请明细保留原输入；确认另存快照及实际物品，不覆盖原申请。开瓶每个明细一瓶并单独留图；整瓶数量汇总在同一物品。收存时间取服务端当前时间，按门店 ZoneId 加自然月后转 UTC；到达 expiresAt 即不可领取。规则版本追加，不回写旧物品。

领取意图：顾客创建即 authorized；商户创建 awaiting_authorization，顾客扫码后 authorized；商户完成后 completed，或 cancelled。代码使用独立 WS 随机能力令牌，意图表仅存摘要（幂等命令响应保留原码供安全重试）、有效期 5 分钟、绑定门店顾客及明细；不接受身份码。意图不预扣、不锁期限。交付锁意图和按 UUID 排序的全部物品，取锁后时间，逐项校验期限和数量，一项失败回滚整批，返回问题明细。命令以租户/门店/操作者/操作/幂等键及请求摘要持久化，同键异参 409；事务级 advisory lock 序列化重试。

关闭新业务后，历史查询、撤销、授权既有领取、交付既有物品仍须身份、门店及对应 RBAC；申请、新规则和新收存必须通过 wine_storage AppGate。到期与实物处置分开，本版不自动处置、不提供过期领取或延期。

再次寄存必须引用已完成领取及原明细，不能超过已领取且尚未用于再次申请的数量，重新上传照片和走实际收存确认。纠错仅追加说明、操作者、原因及原记录引用，不改写已完成业务、不延长期限。

## 数据库检查

V077：catalog 价格可空、仅限 storage 资料；新增寄存表，租户/门店/顾客复合 FK，数量、状态、版本约束，所有操作依赖作用域。照片 JPG/PNG <=5 MiB、<=3000万像素，复用现有图片验证器并通过鉴权二进制接口访问；不保存外链。图片一经上传不可覆盖，申请/收存/补充以 phase 区分。新增索引覆盖门店/顾客列表、到期和意图。无删除接口。回滚应用须保留新增表及 NULL 价格，不逆向破坏已建档记录。

- 中英文/编号检索；未审核建议不可见；关联已有或新建 storage-only NULL 价格产品。
