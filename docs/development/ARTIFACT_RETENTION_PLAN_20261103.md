# 发布制品自动清理实施规格

用户已授权实现、验证、提交、推送和生产部署；先dry-run核验，再启用。保留所有现有无关工作。仅Python运维脚本、systemd和发布规范；不改变业务、数据库或应用版本。

1. 原备份策略保持15天、至少2份经pg_restore目录验证的完整恢复点和2份前端快照。新增根目录固定为/opt/rpb/releases、/opt/rpb/staging；不赋予服务/home/ubuntu写权限，不管理日志、生产app/frontend/media或数据库。
2. 根拥有的独立登记库记录类型、文件哈希、发布成功时间、独立前后端SHA、回退引用。未登记、未完成、异常目录、符号链接、越界文件一律保留。注册信息不能来自上传文件自声明。
3. 成功发布制品超过15天且不属于当前版本、最近2组成功版本、固定项或回退依赖才可清理。成功上传副本超过24小时，且受保护原件哈希一致才可清理。保留原件不能进入同轮删除清单。
4. 新发布通过统一制品CLI创建staging、准备版本、完成登记、生成回退快照与容量检查。相同JAR以校验后的硬链接复用；前端快照只保存该次版本文件，不拷贝在线累积历史assets。新格式备份只通过可信登记清单识别，不扩大文件后缀白名单；历史unknown保持原状。
5. 与发布共用独占锁；plan默认不删除；执行前复核全部候选、哈希、保留原件、版本和备份数量，再使用无符号链接的目录描述符逐个删除，空目录仅rmdir。中断或清单漂移按阻止清理处理，不自动扩大范围。
6. 可用空间<5GiB预警、<2GiB严重；发布预算必须留2GiB余量，磁盘紧张不降低保护条件。状态写入本地运维告警/最近结果，不擅自向外部账号发通知。

## 验证清单

旧16项回归；日期边界、当前前后端SHA不同、最近2版本、回退引用、缺少恢复点、未知文件/日志、符号链接和越界、伪造登记、上传原件哈希变化、相同原件本轮保护、重复执行、执行前文件漂移、硬链接空间、发布锁、剩余容量、归档路径逃逸、仅备份版本前端文件、服务写权限与dry-run开关。

生产先备份原脚本/单元/策略，安装关闭managed apply的版本，手动及systemd各运行dry-run；确认候选和保护清单后开启。业务服务不重启。失败恢复原运维文件及timer；不回滚数据库，不恢复已清理的可重建制品。
