# 单商品单条码（2026-10-26）

## 合约与原因
原编辑器通过数组循环和添加按钮支持多个条码，后端亦未限制商品条码数量。每个商品现在允许零或一个条码。扫码原样填写/替换唯一输入框，不补位；删除添加按钮，照片仍非必填。

沿用 /api/v1 门店目录下产品 editor 和 barcodes 接口与数组 DTO，编辑器 desired barcodes 最多一条。legacy barcodes 写入在商品行锁下拒绝产生第二条，返回 CATALOG_SINGLE_BARCODE / 409。批量编辑多条同样返回该错误。商品、条码、版本及幂等命令必须一起回滚。权限、租户和门店隔离不变。

旧多条数据读取不删除；界面提示明确选择保留的一条，保留完整 expectedBarcodes 快照以防并发覆盖；也可明确清空。只有统一保存后删除未保留项。不做猜测性数据库清理，无迁移；所有写入路径复用商品行锁串行校验。旧成功幂等记录原样重放。

## 测试清单
- 独立接口拒绝第二条，原条码与新原样表示仍可保存，替换可用。
- 统一编辑拒绝两条且商品回滚；旧多条可显式合并，原快照参与校验。
- 前端只一个输入框、无添加按钮，扫码一次启动并替换；空商品可直接填写。
- 旧多条未选择不能提交，明确选择后一次保存；权限及原有回归沿用。

## 发布范围
本轮为本地实现，未提交、未部署。保留之前寄存商品资格修复及其他已有改动。上线需用户后续明确授权。回退可恢复本次代码，不涉及数据结构回退；已明确移除的旧条码需根据审计另行核实，不能猜测恢复。

## 审查记录
- API：沿用资源路径与 DTO；新增 CATALOG_SINGLE_BARCODE/409。管理权限、作用域、幂等校验不变；不扩展匿名访问。
- 数据库：无迁移、无生产 SQL。条码写入仅在 CatalogBarcodeService 两个入口；均锁同一商品行再写入，独立写入拒绝第二条，统一编辑限制 desired 数量。租户条码唯一索引及原样值约束继续保留。
- 回滚：统一编辑失败回滚商品、条码及命令记录；原始条码快照用于拒绝过时更新。
- 测试：新增独立接口第二条拒绝、统一保存两条拒绝及商品回滚；旧多条快照测试仅构造隔离测试数据，不表示真实已有重复。

- 用户澄清当前没有保存两条记录，因此无需实际数据清理。防御性旧数据选择只在接口返回多条时显示。
- 红灯证据：target/catalog-single-barcode-red.log 两个新增后端测试明确复现旧实现未拒绝第二条。首次前端红灯输出因断言打印大型 Vue 节点而占用内存，已仅终止本轮进程，改用布尔断言。
