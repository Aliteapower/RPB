## 实现与模块边界

- 顾客仅保留“出示个人钱包码”可见出码入口，旧code查询参数兼容统一页面；说明“此码可用于钱包付款、充值及积分办理，请当面出示。”。没有资金账户或未启用付款也能出码办理身份业务。
- 独立 personalpayment 模块管理限额、顾客同意、付款快照与单账单绑定，沿用WI身份仓储；充值与积分共用原入口。真正扣款仍由原资金分摊、账单、幂等、审计负责，积分不抵现金。
- 商户消费页先填金额说明，扫本次有效个人码即提交，不能从之前选客状态扣款。充值/积分先扫码，核对顾客后选操作，保留实际收款确认和独立权限。
- 顾客明确同意当前单笔上限和规则后才启用免逐笔确认；限额提高、包括先降后升，要求重新同意。实际直扣受当前策略、当前同意及签发快照三重限制。超限建立唯一待确认原账单，未经本人确认不扣款，确认时全额校验。
- 每码60秒，可刷新，成功付款自动换码；身份读取不消耗付款次数。重复请求返回同一原交易，不同请求编号不能再次使用同码。未知结果保存编号与非令牌意图，先查询，再reconcile；确认为未执行才封存原编号并允许重扫。旧页面迟到响应不能删除新页面的请求恢复信息。
- 旧WC/WP和逐笔quote/pay接口保留，旧WC直接扫码扣款HTTP入口安全返回409，要求新流程或逐笔确认，避免绕过新规则。旧明确确认支付保持兼容。
