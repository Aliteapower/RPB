# 工资分类及真实汇总表核对

## 实现边界
工资模块继续拥有计薪、方案和付款；reporting仅投影快照，statutory继续解析管理员保存的规则版本。新纯投影PayBreakdown与共享Vue组件负责分类显示，不重算历史工资。PayItemKinds集中限定计算含义，名称、金额及项目增删仍在既有模板、个人方案、本月调整中维护。

收入：基本工资、加班、额外普通工资、津贴、现金住宿津贴；报销单列。员工扣项：其他扣项、已确认CDAC、员工CPF。雇主费用：雇主CPF、SDL、其他雇主承担。CDAC是已核对金额配置，本轮没有引入族群推断或自动CDAC缴费规则；AW/AWS、非现金住宿待遇不作为普通收入处理。

计划付款方式与银行在个人薪资方案独立维护，随工资方案冻结。付款登记的实际方式、银行和参考号分别保存，支持cash/bank/paynow/other；付款只是登记，不向银行转账。旧方案缺字段继续显示未设置，旧银行付款没有收款银行名称时保留未知，不凭交易参考号推断。新增银行付款须填银行；旧请求原样重放和旧付款冲正兼容。

## 本项目本地演算
独立新增一名停用的合成员工，属于原测试南区公司、2026年9月（已离职合成记录），不参与现有10月排班。基本工资1800，额外普通工资100，津贴50，现金住宿津贴200；报销20，其他扣项400，CDAC1，其他雇主承担30。使用当前已保存的2026规则v1。

## 数据库与兼容审查
V102仅为付款表增加可空bank列并将paynow纳入已有method CHECK；旧bank保持null，无回填、金额更新、删除或外键变化。方案可选payment保存在原JSON，null不序列化，旧方案往返JSON保持相同哈希。读取员工生日时构造计算用方案也保留payment，避免丢掉计划付款资料。

公司/员工/付款CSV保留原列顺序并末尾追加字段，工资项目CSV按项目逐行导出（包括员工CPF、雇主CPF、SDL）；文本名称、银行继续防公式注入。新增CSV列属于导出扩展，依赖固定列数的外部使用方需按列名读取。
