# 跨产品顾客查询统一优化（2026-11-03）

## 审计与改动

| 产品/入口 | 原情况 | 本次处理 |
| --- | --- | --- |
| 卡券持卡核销 | 已发布唯一顾客直接选中和更换/清空 | 保留并纳入回归 |
| 钱包充值、退款顾客选择、积分业务 | 查到唯一顾客仍需点击结果 | 公共WalletStaffCustomerPicker自动选中；新增清空，更换保留查询词 |
| 按手机号办理钱包充值/积分 | 选择候选后还要再确认顾客 | 唯一手机号匹配直接选中；多条仅点击一次；保留完整手机号验证和最终业务确认 |
| 酒存存酒/取酒及同号顾客建档回查 | 查询后再点击顾客 | useMerchantStorage统一选择；保留原有更换/清除、业务草稿销毁及历史记录 |
| 预订、排队、直接入座 | StaffGuestContactLookup已自动按完整手机号回填 | 无重复选择，不改原有编辑行为 |
| 顾客管理、激活目录、报表、交易记录 | 列表/筛选用途 | 不自动进入编辑或业务；与身份选择区分 |
| 收款、日账、人事、产品目录 | 扫码/支付确认、报表或员工/商品搜索 | 未发现同类顾客二次选择，不修改其业务边界 |

新增规范 `docs/frontend/CUSTOMER_LOOKUP_STANDARD.md`。复用各模块已有API、布局和权限，不增加通用大组件或另一套顾客目录。

钱包选择现有账户仍可读取余额，但自动选择调用choose的createIfMissing=false，不会因查询产生开户POST。明确开户按钮仅在钱包充值场景、无已有账户且有原有开通权限时出现；积分/退款身份选择不会新开户。手机号确认标记仅表示当前选中的业务顾客，不是短信验证或扣款授权。扫描个人码、充值实际到账确认、积分操作二次确认、卡券授权与酒存实物核对不变。

钱包查询增加可失效的lookup版本，组件编辑/离开后取消旧查询结果；酒存查询、任务切换及卸载也使旧结果失效。顾客清空仍复用原有账户/身份清理、顾客ID键控业务表单及操作后重置，不删除历史数据。
