# 酒水寄存实施自审

日期：2026-10-25。范围：本地开发及验证。本报告是实现者自审，不代表生产发布或独立外部审查。详细证据见 WINE_STORAGE_VERIFICATION.md。

# API Review Report

## Endpoint

顾客 `/api/v1/public/stores/{storeId}/wine-storage`；商户 `/api/v1/stores/{storeId}/wine-storage`。接口及 DTO 见 `docs/api/WINE_STORAGE_API.md`。沿用现有门店产品开关 PUT 接口。

## Contract Check

使用明确的命令/视图 record，控制器不暴露持久化实体、不访问 Repository。瓶数和月份 opt-in 严格整数反序列化，业务层负责正数、上限、开瓶整件、数量和状态。所有时间以 UTC 交换，物品冻结门店时区和规则版本。相机识别与物品履约分开，扫码解析不扣减。

## Permission Check

身份复用 CurrentActor 与 CustomerAuth session cookie；商户还要求 tenant/store 分配及 wine_storage 对应权限。新申请、规则和实际收存通过 AppGate、租户授权、门店商业授权及开关。既有履约和历史不要求继续开展新业务，但仍严格校验身份、门店、顾客及交付权限。关闭后的开关管理入口保留。

新产品建议不是产品管理权限，只有商户收存审核才通过 catalog 的窄入口创建当前门店 storage-only 的未定价建档产品。

## Error Mapping

401 未登录；403 权限、商业授权或开关拒绝；404 不存在或非本归属；400 字段、数量格式或图片错误；409 状态、期限、数量、幂等键冲突。批量冲突包含 itemId/code，前端显示对应酒品及原因。照片接口 private/no-store，并要求持有人或对应门店商户权限；写请求要求专用头并拒绝跨站提交。

## Replay / Idempotency

命令以 tenant/store/actor/type/operation/key 作为持久唯一边界；事务级 advisory lock 序列化同命令，规范化 Map 键序后摘要校验同键同参。缓存结果和业务修改在同事务提交。不同键重复交付仍由意图状态拒绝。领取意图行锁、物品 UUID 固定顺序锁和最终实时到期检查保证整批全成全败，不使用通用身份码扣减。

意图表存代码摘要；幂等响应保留原码供该操作者安全重试，历史查询不返回原码。令牌随机、5 分钟有效、绑定顾客/门店/明细/数量。跨 JVM 重启的同命令重试实际验证，返回原结果，仅一笔扣减和一条交付流水。

## Compatibility

目录新增 NULL 价格语义并补齐读取、编辑及销售校验；原有明确价格、零价和税务数据不改写。钱包新增入口和扫码适配，不承担寄存规则。共享扫码组件只增加可选展示参数，原付款/积分/卡调用保留默认提示和解析边界。本地 allowlist 只新增实际 GET/POST 路径，没有修改生产认证或放宽其他产品入口。

## Missing Items

真实手机摄像头及相册验收、系统文件选择器完整验收、大容量压力测试和生产验证不在本轮完成证据内。没有已知必须通过绕过期限或修改旧业务才能解决的阻塞。

# Database Review Report

## Migration Scope

V077：目录价格/税务可空，新寄存规则、申请/明细、物品、照片/一次绑定、意图/明细、再次寄存关联、建议审核、流水、幂等命令及 AppGate 注册。没有给真实租户开通或虚构商业价格。

## Table Check

租户共享产品身份和分类仍在 catalog；门店投放仍在 catalog_product_stores。顾客实物数量只在 wine_storage_items，资金/积分/卡次数/可售库存无写入依赖。申请与确认分别保存，实际物品保存产品/规则/照片快照。期限与 physical_disposition 分离，首版不自动处置。

申请保留创建/更新时间；规则版本、附件、命令和流水追加创建时间；实际收存、完成交付和审核各有自己的 UTC 时间，后续操作由事件保留操作者与时间，不靠覆盖旧时间表达历史。

## Constraint Check

复合 FK 限制 tenant/store/customer；分类和产品引用限租户；规则限门店；明细和领取引用限同一顾客门店。CHECK 限数量、开瓶数量 1、状态、期限和渠道。照片 ID 只能绑定一次，不提供更新图片或删除接口。再次寄存必须关联已完成领取，锁定原意图核对已用额度，收存时按实际修正数量计算额度。

## Index Check

门店/顾客申请列表、物品到期、意图历史、事件、照片归属均有查询索引；唯一键覆盖幂等和规则版本。照片按主键鉴权读取。首版历史列表未做大数据压力验收，后续可按实际规模增加分页/归档，不能以此省略权限过滤。

## Tenant Isolation

查询和锁操作均携带 StoreScope；顾客查询还带 customer_id 或显式 own 检查。商户目录候选允许同租户共享产品，顾客只见当前门店正式开放的 storage 产品。上传、绑定和读取分别检查归属及阶段。真实 HTTP 验证跨店/跨顾客混合领取整批拒绝、不影响合法选中项。

## Risk

NULL 价格意味着旧目录客户端/旧版本代码不能无条件拿价格做运算。没有逆向删表回滚；照片和流水需继续保留。本地迁移验证不等于已授权生产执行。

## Recommendation

保留迁移与快照语义；只有完成真实设备和发布准备后，另行按明确授权安排生产工作。
