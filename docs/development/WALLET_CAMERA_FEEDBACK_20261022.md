# 手机扫码与收款结果优化

本文件记录本地实现阶段；后续已按用户授权提交部署，版本与线上证据见 [发布记录](WALLET_UI_CAMERA_PRODUCTION_RELEASE_20261022.md)。

## 范围与方案

- 点击员工“扫顾客付款码”或顾客“扫一扫”后，直接请求摄像头，优先后置；保留手动打开、相册与粘贴。iPhone使用静音内联预览，权限受限时有具体提示及重试，不循环弹授权。
- 摄像头生命周期、图像解码和界面分离；切前后摄像头前释放旧流，手电筒仅在设备支持时显示。页面后台、离开、停止及识别后释放摄像头；迟到的授权/播放结果不得复活或关闭新的摄像头。
- 只接受当前入口对应的钱包码，普通二维码继续扫描并提示；识别只进入服务端校验，禁止自动扣款。
- 两端原单详情显示明确结果：全额已收显示成功；扣了部分钱包显示已扣及待补；零余额不显示扣款成功；归档/过期/失败/退款不误报成功。员工通过原单轮询收到顾客确认结果，新增醒目的可关闭提示，不因重复轮询重复提示。
- 本轮仅前端及测试、文档，不改变资金API、事务、平台计费或权限，不提交部署，保留之前的UI及其他改动。

## 测试清单

- 摄像头后置优先、静音内联、重复启动、停止/后台/卸载、异步授权与播放竞态、拒绝授权/无设备/设备占用/非HTTPS、约束降级、切换及手电筒能力。
- 每帧只识别一次；错误码型继续扫描；图像解码异常可恢复；识别不产生支付请求。
- 结果完整付款/部分付款/零余额/线下补付/退款关闭、初次查看和重复轮询、不同原单隔离。
- 相关前端回归、TypeScript及生产构建、本地隔离测试库浏览器虚拟金额联调；真实手机硬件及微信权限无法由桌面视口替代，分别标明验证程度。

## 实现与验证结果

- `scanning/cameraSession.ts` 单独管理摄像头租约、约束降级、前后切换、可选补光、帧节流与资源释放；`qrDecoder.ts` 负责中心区域/周期全画面及图片解码；`walletQr.ts` 只做码型及同源链接检查。`WalletQrScanner.vue` 负责交互、状态、页面后台停止及图片操作，不含资金调用。
- 员工和顾客扫码入口均直接请求后置摄像头，静音内联播放；拒绝权限、设备缺失/占用、播放限制、非安全连接、系统中断等分别提示。等待授权可随时停止，进入后台不自动复活摄像头。不支持手电筒的设备隐藏该操作。
- `paymentResult.ts` 从服务端账单计算结果，`WalletPaymentResult.vue` 供两端详情复用：持久结果卡片及状态变化时8秒可关闭浮层。全额成功为绿色，待补为橙色；兼容设备在前台可短振动，iPhone不依赖振动。初次查看历史单不弹浮层，重复轮询不重复提示，关闭或退款隐藏旧成功提示。
- 前端共30项测试通过（原有14项＋摄像头13项＋收款状态3项），0失败/跳过。新增16项在最后复核后再次通过；`vue-tsc`及Vite生产构建通过。测试日志：`target/wallet-camera-regression.log`、`target/wallet-camera-tests.log`、`target/wallet-camera-build.log`。后端业务未改，沿用同一代码状态上轮189项后端回归证据，没有重复宣称本轮重跑。
