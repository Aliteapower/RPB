# 新增产品线开发需求与代码审计

日期：2026-10-22。项目：`D:\RPB`。审计基线：`311cce291d5efd8f89d988ec87edb63ce2084dfc`。

本文件是新增产品线的通用接入需求，覆盖统一租户资料、组织与账号、产品目录、平台计费、授权、前后端接入、数据迁移及验收。具体新产品的名称、业务流程、价格和计费范围需在其专项需求中补齐。本次仅新增文档，没有实施下述代码变更或生产操作。

## 1. 核心结论

1. 新产品接入 RPB 现有平台，复用同一套租户、经营主体、门店、账号与门店授权；不得按产品线再建租户档案或员工登录体系。
2. **新增产品线使用的租户资料由平台统一管理，各产品读取同一权威数据源。**“统一”是同一租户在多个产品间统一，仍严格隔离不同租户。
3. 租户资料并非全部属于租户级：租户身份与共享 Logo、经营主体负责人、门店名称和联系方式各有归属，不能为了统一而把多门店信息压成一条。
4. 新产品复用 `platform_apps`、价格模板、订阅、门店订阅明细、订阅事件及 App Gate，不建立另一套收费或授权状态。
5. 平台产品订阅收费与商户向顾客收取的 PayNow 款项属于不同业务。新产品开通沿用平台人工登记和授权流程，不能借用商户支付成功状态代替平台订阅。
6. 现有代码支持多产品，但还不是任意新增目录即可运行的插件系统。入口权限、默认入口路由、账号权限分配和前端导航均需完成接入。

### 2.1 P0：必须保持的安全约束

本次未通过运行时验证确认新的 P0 漏洞；以下是新增产品不得破坏的交付红线：

- 业务租户身份从认证上下文取得；平台管理接口可显式指定租户，但必须校验平台权限。
- 业务查询、更新、导出、媒体读取与异步任务均带作用域；仅凭记录 ID 或门店 ID 不得读取其他租户数据。
- 引用门店及经营主体时必须校验同租户关系；数据库使用适当复合外键和唯一约束兜底。
- 产品开通不等于用户有业务权限；用户有权限也不等于租户已购买产品。

### 2.3 P1/P2：计费扩展前必须明确的现有限制

以下是静态代码确认的能力边界，是否实施增强取决于新产品商业规则，不自动扩大为本次开发范围。

- **单店到期不会直接触发单店 App Gate 拒绝。**`AppGateService.evaluate` 未读取门店计费明细；`updateAggregateFromItems`（`ProductSubscriptionService.java:437`）以有效状态明细的最大结束时间更新聚合授权，兄弟门店可存在不同到期日。若要求“未续费的店停用、其他店继续”，必须增加明确的门店有效期授权规则与回归测试，不能只做单店续费页面。
- **未来生效时间需补规则。**`AppGateService.java:113` 检查 `valid_until`，当前评估流程未检查 `valid_from`。若允许预约生效的新订阅，必须校验开始时间，同时保证提前续费不截断当前可用期。
- **部分门店购买并未由整体购买接口提供。**`prepareMutation` 使用全部有效门店；如需勾选购买，应增加明确选择契约和服务端归属校验，禁止只在界面筛选、后台仍全店收费。
- **单店独立暂停/取消不能视为已有能力。**当前控制器提供单明细续费，但暂停/取消是订阅整体操作；细分店操作需补命令、聚合和审计。
- **幂等重放目前不是请求内容一致性证明。**`ProductSubscriptionService.java:325` 的重放按租户、产品、事件类型、幂等键寻找订阅，再返回当前状态。需要同键异参拒绝、跨明细键冲突识别或返回原操作结果时，应补请求摘要、目标绑定和响应快照。
- **多币种需要限制。**报价允许请求覆盖模板币种，聚合又直接相加各有效明细金额；应在新产品计费契约中要求同一订阅币种一致。币种转换需要单独业务设计，不能只改币种代码。

## 3. 统一资料与数据归属需求

### 3.1 唯一权威来源

| 数据 | 权威归属 | 新产品使用方式 |
|---|---|---|
| 租户 ID、编码、生命周期 | 平台租户管理 `tenants` | 引用既有租户 ID，不生成产品专用租户 |
| 共享品牌 Logo | `tenants.logo_media_asset_id` 与现有媒体服务 | 经授权读取；清除后不得被旧产品配置重新恢复 |
| 经营主体名称、负责人等 | `operating_entities`；遵循现有回退规则 | 引用同租户经营主体，不将经营主体 ID 作为租户 ID |
| 门店 ID、编码、名称、联系地址及电话 | `stores` 及现有统一资料维护服务 | 读取当前门店资料，不在产品设置中重复维护 |
| 门店时区、语言、币种和显示格式 | 平台门店配置 | 用于业务日期与展示；产品专用口径须显式命名，不覆盖公共配置 |
| 员工账号、角色、门店访问权 | `auth_accounts`、权限及 `auth_account_store_access` | 复用登录、停用、改密、门店切换及授权 |
| 客户身份（如产品需要） | 既有租户级客户模块 | 同租户共享客户 ID，不复制第二套客户通讯录 |
| 产品业务配置与记录 | 新产品模块自己的表 | 按租户/门店隔离，保存产品专有信息 |
| 产品、价格、订阅及商业操作事件 | `platformbilling` 与 App Gate 所属表 | 复用平台能力，不写进产品业务设置 |

补充规则：

1. “平台统一维护”允许已有租户管理员在授权范围内自维护，并非只有平台管理员能修改；各产品不得提供另一套资料写入逻辑。
2. 共享资料由窄查询接口/适配器提供，新产品不直接拼接其他模块的写表 SQL。展示所需字段按最小权限暴露；普通员工不直接借用管理员资料维护接口。
3. 如需英文/多语言名称，先核实平台公共字段或既有 i18n 目录能力；缺失时在公共资料边界扩展，不沿用某个产品的私有英文名作为全平台权威来源。
4. 资料变更后，各产品下次读取或按约定刷新应获得一致信息；如有缓存，须明确失效策略及门店切换时的清理。
5. 历史凭证确需冻结名称等资料时，可保存标注时间与来源的业务快照。快照只用于历史呈现，不反写当前资料。
6. 同租户两家门店可有不同名称、地址和经营主体；共享 Logo 变更影响该租户各门店，界面须清楚表达作用范围。

### 3.2 统一使用流程

平台选择已有租户 → 选择该租户经营主体与门店 → 选择产品及计费方案 → 查看报价并登记开通 → 平台生成/更新订阅及授权 → 有该店访问权和产品权限的账号使用产品。

已有租户开第二条产品线不重新注册租户、不重建门店、不重新创建管理员；仅增加该产品的商业授权和角色允许的业务权限。

## 4. 平台产品目录与计费需求

### 4.1 产品定义

- 一个产品线使用一个稳定唯一的 `app_key`，复用 `platform_apps`；显示名可改，标识不得因改名变化。
- 定义名称、说明、排序、平台启停、默认入口、入口权限及必要产品配置；入口必须是项目已实现的受控站内路由。
- 产品注册与租户开通分离。新增目录和价格不得自动为所有租户开通，也不得因回填账号权限而绕过订阅。
- 平台产品目录管理与平台计费使用已有平台权限体系；产品用户不能维护全局目录或其他租户订阅。

### 4.2 价格与报价

- 复用 `platform_product_line_prices`，支持现有月/年周期、金额、币种、启停和版本校验；具体价格由新产品需求定义，不复制现有产品价格。
- 沿用默认按有效门店计费模式时，报价为“周期单价 × 周期数 × 计费门店数”。单店续费仅计算目标店。若采用租户包价、用量价或组合套餐，须单独补计费模型，不能伪装成门店数量。
- 明确界面列出：租户、经营主体、门店、产品、周期、时长、起止时间、单价、默认金额、实收/登记金额、币种和备注。
- 延续现有允许人工覆盖金额的能力，但必须保留默认报价与实际登记金额的审计依据；优惠/赠送 0 金额应有说明，不把空金额默认为免费开通。
- 金额使用十进制类型；统一精度、舍入及分摊尾差规则。模板调整仅影响新报价，不重写已发生的历史收费事件。
- 未配置有效价格、计费范围为空、无效周期/时长、负金额、币种冲突均给出明确失败结果；前后端采用同一校验口径。

### 4.3 订阅操作

| 操作 | 必须实现/复用的行为 |
|---|---|
| 购买 | 验证租户和产品状态、计费范围及价格；生成订阅、门店明细和事件；事务内同步授权 |
| 整体续费 | 明确会影响哪些店；有效期内续费衔接原到期日，已到期从当前时间开始；保留原可用期间 |
| 单店续费 | 绑定目标明细与租户、产品、门店；不覆盖其他店期间和金额；重算聚合状态 |
| 暂停 | 默认复用整条订阅暂停；授权同步为暂停，其他产品不受影响；不删除业务数据 |
| 取消 | 默认复用整条订阅取消；撤销该产品授权，保留订阅事件和业务数据 |
| 历史授权转换 | 显式确认永久授权转收费；保留历史来源，不批量改写其他历史授权 |
| 到期展示 | 根据时间计算有效状态，界面与接口拒绝原因一致；不把聚合到期日显示为所有店共同到期日 |
| 恢复使用 | 明确暂停/取消后走何种受支持命令恢复；禁止直接改数据库制造可用状态 |

按店计费是当前基础；“按店到期自动停用”“单店首次开通/暂停/取消”“任选部分门店购买”属于需在专项需求明确的增强项。若新产品要求这些行为，作为该产品上线前置条件实施，不能以聚合授权近似替代。

### 4.4 收款、事件与一致性

1. 本阶段默认沿用人工收款登记与开通，收款备注、操作人、时间及前后状态需可追踪。产品开通成功表示平台完成登记和授权，不表示第三方支付已确认。
2. 复用 `tenant_product_subscriptions`、`tenant_product_subscription_items`、`tenant_product_subscription_events`。聚合金额须说明是当前明细金额，不能被当成累计实收或财务流水总额。
3. 价格报价、订阅及明细变更、事件记录、授权同步在一致事务边界完成；失败不能留下“已记账未开通”或“已开通未记账”的局部状态。
4. 沿用并发版本机制；新增命令应要求明确版本，拒绝过期修改。幂等键需绑定业务目标，若补强同键异参处理，应与旧接口兼容并增加契约测试。
5. 启用、暂停、取消、改价和人工调价均保留可追溯记录；关键事件保存报价依据、目标门店、周期、币种、金额及操作者。
6. 自动扣款、支付网关、税票、退款、对账、催缴、租户自助结算和 Webhook 不作为通用接入默认范围。需要时另补专项需求及状态机。

## 5. 授权与入口需求

- 复用 `@RequireAppGate` 或现有等价强制评估入口；覆盖产品页面调用的所有受保护接口、导出、附件/Logo 和后台任务。
- 门店型产品的标准允许条件为：产品启用 ∧ 租户授权有效 ∧ 门店产品启用 ∧ 账号可访问该店 ∧ 接口权限满足。若增加单店到期规则，还必须校验该店商业有效期。
- `entry_visible` 只控制导航展示；`is_enabled` 控制门店产品开关。隐藏导航不能代替接口拒绝。
- 维护产品入口权限、只读/写入/设置等权限集合，并覆盖平台创建租户管理员、创建门店管理员、租户创建员工、已有账号权限回填等路径。
- 权限按角色职责分配，设置及管理员更正等高权限不能默认授予普通员工；永久权限与商业订阅是独立条件。
- 门店切换后刷新资料、产品列表与业务数据，防止沿用上一个门店缓存；直达 URL 与导航进入适用同样后端检查。
- 未开通、到期、暂停、产品禁用、门店关闭、无门店访问权、无动作权限，须保留稳定可区分的错误契约。

## 6. 模块与接口要求

- 后端新增独立产品包，按 `api / application / domain / persistence` 分责；前端放入 `src/modules/<product>`，拆分 API、类型、页面、组件和产品业务状态。
- 产品业务模块通过统一资料查询边界与授权边界依赖平台，不把计费判断散落进业务服务，也不依赖订位或 PayNow 的业务规则。
- 共享资料和权限初始化如需扩展，修改归属模块；不为新产品大范围重构所有既有产品。
- 门店型业务 API 沿用 `/api/v1/stores/{storeId}/<product>` 风格；显式 DTO、分页/时间范围限制、稳定错误映射、必要幂等与乐观锁。
- 产品订阅复用 `/api/v1/platform/tenants/{tenantId}/product-subscriptions` 下现有购买、续费、单明细续费、暂停、取消和转换接口；新增行为先补契约。
- 新产品注册路由、员工入口、租户后台入口及中英文 i18n；日期/时间遵循平台显示配置，API 时间继续使用既有 ISO 约定。
- 产品可读取公共展示资料，但不能借此获得资料维护、其他店访问或平台计费权限。

## 7. 数据库、初始化与迁移

1. 仅为产品专有数据新增表；租户级表带 `tenant_id`，门店级表带 `tenant_id + store_id`。索引及业务唯一键包含相应范围。
2. 使用 Flyway 增量迁移注册产品、必要价格及权限；不得改写已执行的旧迁移，不在全局迁移塞入真实商户业务数据或密码。
3. 权限回填按职责且可重入；确保新增账号与已有账号策略一致。新增权限本身不能自动开放产品使用权。
4. 外部系统迁入时明确旧租户/门店与平台 ID 的映射，先查重再导入；默认拒绝覆盖同名租户、已有账本或已有平台资料。
5. 导入品牌时优先保留平台当前资料；冲突显式输出，不按“最后一条数据”覆盖。同租户多 Logo 等情况必须处理后再接管。
6. 读取流程不得触发资料迁移写入。迁移有独立开关、范围、幂等标记和结果记录；原文件及来源证据保留。
7. 产品停用或撤回优先关闭入口与授权，保留业务及收费审计数据；不把删除数据作为回滚默认方案。

## 8. 建议开发顺序与交付物

| 阶段 | 工作与交付 | 完成条件 |
|---|---|---|
| 1. 产品定义 | 补具体业务范围、产品标识、角色、价格及计费粒度；明确是否要求单店自动到期 | 需求可映射为业务与验收场景 |
| 2. 平台接入 | 完成受控路由、入口权限、角色初始化、产品及价格注册 | 可创建、编辑并为指定租户开通该产品 |
| 3. 公共资料接入 | 窄查询适配器、品牌显示及必要迁移 | 新产品没有独立租户资料写入源 |
| 4. 产品业务 | 独立模块、API 契约、业务表、前端及审计 | 正常流程、失败路径和隔离行为通过 |
| 5. 计费闭环 | 报价、登记、续费、暂停/取消和授权同步；按需补单店规则 | 商业状态、可用状态和界面一致 |
| 6. 验证交付 | 测试结果、数据库验证、浏览器证据、变更说明和剩余风险 | 验收矩阵有实际证据；生产发布另行授权 |

专项需求尚需给定：产品名称与 `app_key`、业务功能和数据模型、月/年价格、计费门店选择规则、到期停用粒度，以及是否存在导入来源。未给定前不填假定价格、不创建租户、不改变现有授权。

## 9. 验收矩阵

| 编号 | 场景 | 通过标准 |
|---|---|---|
| AC-01 | 已有租户开第二条产品线 | 租户、经营主体、门店、账号 ID 不变；无重复档案 |
| AC-02 | 共享资料更新 | 同一门店在各产品显示一致；其他门店独有信息及其他租户不变 |
| AC-03 | 清除/更换 Logo | 当前页面使用新状态；迁移接管后的产品不恢复旧 Logo；旧资源不能越权读取 |
| AC-04 | 账号与门店切换 | 同账号按授权切换产品和门店；无权门店不能通过改 URL 访问 |
| AC-05 | 产品创建及编辑 | 受控路由可保存；只改名称不会因独立入口路由被拒；未知入口被拒 |
| AC-06 | 开通与拒绝 | 注册未购买不可用；购买后仅符合角色和门店访问权的账号可用；直调 API 受保护 |
| AC-07 | 月年报价与调价 | 模板、时长、门店数、默认/实收金额、币种及舍入正确；历史事件不随模板变化 |
| AC-08 | 整体购买与续费 | 作用门店清晰；有效期内衔接、过期后重启；不误收其他租户或错误门店 |
| AC-09 | 单店续费 | 只修改目标明细，兄弟门店不被改期/改价；聚合金额和期间符合定义 |
| AC-10 | 暂停与取消 | 对应产品不可用，其他产品继续使用，历史记录保留；恢复遵循明确命令 |
| AC-11 | 单店到期（要求时） | 同租户 A 店到期不可用，B 店未到期仍可用；无需靠人工关门店开关兜底 |
| AC-12 | 未来生效（要求时） | 生效前不可用；续费仍保留当前有效访问，不因下一周期开始日拒绝 |
| AC-13 | 并发与幂等 | 重试不重复收费登记/延期；过期版本拒绝；新增同键异参规则有目标绑定测试 |
| AC-14 | 事务失败 | 故障后订阅、明细、事件与授权不残留局部提交 |
| AC-15 | 持久化与隔离 | 真实 PostgreSQL 验证作用域、复合外键、唯一键及跨租户/店的读取、写入、导出拒绝 |
| AC-16 | 迁移与权限回填 | 不覆盖现有资料；新老账号职责一致；权限回填不自动购买产品 |
| AC-17 | 前端及回归 | 类型检查和构建通过；浏览器验证菜单、直达、失败态、刷新及门店切换；原有订位、支付、营业记录不受破坏 |

本地真实数据库验证必须使用本工作区 `target/local-postgres-current.txt` 指定的运行时；缺失或失效时按 `docs/development/LOCAL_RUNTIME_QUICK_RESTART_GUIDE.md` 修复，禁止回落其他库。
