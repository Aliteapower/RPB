# 全产品线开通与历史访问一致性（2026-10-26）

覆盖代码注册的预订排队、收款、钱包积分（含卡）、酒水寄存、每日营业记录。正常业务与历史查询分别发现，未开通不展示，已开通正常使用；曾开通关闭/到期后保留有权限的只读历史入口，不能借历史模式新建、编辑、收款或扣减。新增历史通道仍拒绝平台全局停用、权限撤销及跨租户/门店访问。钱包、积分原账冲正及酒水受控领取继续遵循原模块的历史权限与审计规则，不因入口统一而取消。

## API 合约
/api/me/apps 保持 apps 为正常业务入口，新增可选 historyApps 数组；匿名两数组为空。历史权限与路由来自代码清单，不接受数据库配置任意路由。历史入口不混入 apps；旧客户端可忽略新字段。管理产品线支持同一清单的五个产品；从未开通仍省略，关闭控制保留。续费不能自动覆盖管理员显式关闭状态。
@RequireAppGate 增加 allowClosedHistory，只有显式标注且 GET/HEAD 并持有登记的查询权限才能使用历史通道；写方法仍走正常 gate。Ledger 查询应用服务也检查历史权限，命令仍严格检查正常 gate。只对预订列表/日历、收款记录/账单查看、营业记录查询开放历史通道。
历史授权依赖平台产品 active、实际开通过的本租户/门店关系、门店曾启用记录以及员工原查询权限。订阅到期不会抹去数据所有权，但不能恢复营业写入。平台全局禁用或权限撤销不能用历史模式绕过。

## 前端
工作台和租户侧栏增加独立历史查询区；员工底部导航加载期不默认显示未核实业务。历史链接进入现有只读页面/历史模式；预订隐藏操作，账本不挂载编辑器或设置。其他历史查询沿用原模块权限及数据范围，用户输入与金额快照不改写。共享目录独立保留。

## 测试计划
五产品未开通/可用/关闭/到期、权限撤销、跨门店/租户；正常入口与历史入口互斥；GET 历史允许但 POST/PUT/DELETE 不允许；原业务可用行为不变；续费不重开；空态/错误/切换门店晚响应；只读页面不产生写请求。无迁移，无订阅数据改写，保留其他改动。本轮未授权提交部署。

## 最终行为矩阵

| 产品线 | 正常开启 | 关闭或到期后的必要入口 |
| --- | --- | --- |
| 预订排队 | 原预订、排队、桌台操作 | 按日期查预订及排队；隐藏操作按钮 |
| 收款 | 原收款与管理入口 | 独立员工查询路由 `/stores/:storeId/payments/records?history=1`，不要求管理员角色，仍要求原查询权限 |
| 钱包积分及卡 | 原钱包、积分、卡业务 | 钱包/积分流水、卡业务记录和订单查询；历史模式不展示收银和卡业务操作 |
| 酒水寄存 | 存酒、取酒、管理 | 存取记录、原受控取酒；停止新收存入口，隐藏保管员和规则编辑 |
| 每日营业记录 | 记账、历史、设置 | 历史账目及当日明细；不挂载编辑器或设置组件 |

从未开通的产品不会出现在营业目录或历史区；产品线管理只列实际开通过的产品，关闭后仍可在授权有效时重新开启。产品目录、员工/顾客管理等共享能力保持独立。当前菜单清单覆盖代码登记的五条产品线，不新增尚未实现的积分商城、自助购物产品线。
