# 前端版本检测与旧寄存流程拦截

用户授权：版本检测、更新提醒、缓存规则、QA旧标签验证、提交推送与生产发布；保留无关改动，不操作真实顾客数据。

## 设计及验证清单

- 构建内嵌版本并生成 `/frontend-version.json`。初次加载、可见标签每60秒和恢复聚焦时读取，使用no-store；网络失败、无效响应不误报，去重并限制超时。
- 新版提醒在正常文档流显示中英文文案，绝不自动刷新。用户点击更新、阅读未保存内容提醒、再次确认才载入新版；取消保留草稿，不上传或跨门店保存输入。
- HTML和版本清单no-store，hash资源长期immutable缓存，保留旧资源；缺失资源返回404，安全响应头保留。
- 没有检测代码的历史标签无法凭空获得新提示：服务端拦截旧店员创建顾客授权码接口，返回升级提示，不创建意图或扣减库存。历史交付/取消、顾客主动出码保留。
- 测试覆盖同/异版本、网络/解析错误、请求去重、超时/卸载、中英文提醒、更新二次确认、不自动刷新；旧API保留认证、权限、租户校验优先级。
- QA候选A/B切换：发布前打开A、填写草稿，切到B后A提示但输入仍在；暂不更新不刷新，明确确认后进入B。历史无检测版本另验旧业务接口拒绝，不声称能注入提示。
- 发布核对干净源码、前后端范围、历史迁移字节、nginx配置与缓存头、缺失资源、回退点、QA隔离与收尾。

无数据库迁移、订阅或产品线入口改动。旧接口行为变化详见API契约。

## 提交前验证 / 审查

- 116项前端回归通过，含6项版本检测/提醒测试。旧接口先补测试确认原行为失败，再实现；92项寄存后端回归通过，覆盖权限、租户隔离、直接交付、顾客出码和本地安全。数据库测试使用D:/RPB指针61644所指PostgreSQL中的测试独立schema。
- 实际浏览器打开候选A、选择合成顾客、填写未保存酒名/说明/数量2；服务器发布B后A入口未变、出现提醒且三个输入不变。暂不更新继续保留；只有第二次明确确认才载入B入口。中英文及实际320/390手机视口无整页横向溢出。此为候选A/B环境，未使用真实顾客资料。
- 新Nginx配置在隔离配置中nginx -t成功；另启动独立loopback Nginx验证SPA HTML/index/清单no-store、hash资源immutable、缺失资源404不回退HTML、安全头保留。生产配置此阶段未修改。
- Code review：版本检查只读取公开元数据，不导航、不提交业务；卸载/超时保护与请求去重已核对。旧接口拒绝在服务层，先做原访问及顾客范围校验，无Repository/Commands写入；历史交付/取消不变。无迁移或依赖变更，无阻塞审查项。
- Production Readiness：以上验证通过后GO；生产切换前备份JAR、前端、版本标记和Nginx原配置，核对依赖/历史迁移原字节与环境摘要，持有既有独占发布锁。先部署向前兼容后端再切前端/清单，资源保留，nginx -t后reload；验证失败恢复本次JAR/index/版本标记/Nginx配置，不恢复数据库。
- 历史上完全没有检测代码的旧标签不会获得新横幅；旧授权入口返回409升级错误防止继续创建该流程。首次需要用户处理草稿后手动重新载入一次，之后的发布才可自动检测并提醒。
