## 实现范围与职责

| 边界 | 实现 |
|---|---|
| 钱包账户与资金 | `wallet/application/WalletAccountService`、账户 Repository、不可变 Ledger；SGD 整数分，发行主体计划内共享账户，跨租户/主体拒绝 |
| 充值与实收 | `WalletTopupService`、`WalletCollectionService`；现金、PayNow、外部信用卡终端均需员工明确核实，创建单或生成二维码不入账 |
| 消费与授权 | `WalletCheckoutService`、`WalletAuthorizationService`；账单、动态顾客码、商户账单码、60 秒确定金额授权、账户/账单版本、顾客本人确认 |
| 退款与异常 | `WalletRefundService`、`WalletCollectionExceptionService`；原渠道限额分摊、充值退款先冻结、原单失败重试、迟到/超额实收独立登记并退回 |
| 统一资料 | `SharedWalletDirectory` 调用公共组织、资料、Customer/Auth 查询；不复制租户、顾客、品牌或登录体系。顾客生命周期扩展端口与数据库触发器保护资金归属 |
| 收款适配 | `OfflinePayNowCollectionService` / `WalletOfflineCollectionAdapter` 复用原门店资料和 QR Builder；钱包设置可配置同一份门店资料，保留原 quick-pay 配置，不授予 payment 订阅 |
| 平台计费 | `platformbilling/SelectedStoreBillingService` 复用原报价、订阅、按店明细、事件和授权同步；首购/加店显式选择，续费保留兄弟店；钱包价格初始禁用 |
| 前端 | `src/modules/wallet` 按员工工作台、顾客钱包、充值、结算、授权确认、退款、收款配置、对账、扫码组件拆分；接入已有路由、权限、菜单及中英文 |

控制器仅调用应用用例；钱包不读写其他模块私有表。消费、充值入账、分录、幂等响应及审计同库事务提交。异常外部实收/退款只记外部事实，不借此改钱包余额。

## 数据库与授权审查

- 新增 `V057__wallet_product_line.sql`：产品目录、默认禁用的月/年价格、职责权限回填、钱包业务表、平台计费请求快照。**没有给既有租户自动开通钱包或 payment**。
- 复合外键覆盖租户、发行主体、授权门店、账户、顾客及原单；资金分录只追加，分录来源唯一、账户版本唯一。账户余额与分录重算不一致时阻止新资金操作，不静默修数；独立异常外部实收/退款仍可记录且不改钱包。
- 外部实收按渠道/收款账户/凭证去重；外部退款凭证也在原渠道账户命名空间内唯一。退款分摊按分精确取整，累计不超过原已付额。
- 统一 Customer 停用通过扩展端口返回 `CUSTOMER_HAS_RETAINED_ASSETS`；数据库同时阻止绕过应用的归属、合并、删除变更。姓名/联系方式仍从统一资料修改。
- 钱包单店必须存在明确有效的计费明细；租户总授权不能兜底放开钱包。其他产品原有兼容规则保留。到期禁止新充值、消费、授权码和未付款新收款，保留本人查询及受控原单核实/退款。
- PayNow 租户默认资料只作设置预填参考；钱包要求经理核实后保存明确门店配置，避免多个经营主体误共用未经归属确认的收款账户。同店支付产品有效时，钱包修改共用资料还要求原支付设置权限。
- PayNow 正常确认要求填写银行实际收款 UEN/手机号并匹配当前门店资料；渠道停用/资料变更导致旧实收不符时，经理可保留原单事实并按实际原渠道退回，不借异常路径加钱包。没有有效资料时服务端也拒绝新建 PayNow 充值。
- 员工会话与顾客 cookie 分开，租户和顾客 ID 取服务端身份。钱包写操作要求自定义同源头，拒绝跨站及同站跨源提交；本地白名单仅增加必要路径和方法，未知路径仍拒绝。

正式接口见 [钱包 API 契约](../api/2026-10-22-wallet-contract.md)。

## Code Review / TDD Review

结论：**本地实现交付通过，带下述验证限制；没有生产发布结论。**

已修复审查发现：钱包总租户授权绕过单店计费；单店续费重试先撞旧版本；余额不平仍可新建资金单；扫码/旧报价重放；外部实收及退款凭证重复使用；迟到实收无法闭环；共用 PayNow 资料强制依赖另一个产品；原退款待执行额重复包含已退钱包部分；门店/顾客切换时迟到响应覆盖当前选择；已关闭账单仍提示补付。

进一步复查收款资料的停用/变更边界：普通确认不能省略实际账户；经理的异常外部事实不受当前配置启停阻断，并且与钱包入账路径分离。相关适配和全部钱包资金用例复跑通过。

验证重点为真实数据库状态、事务、竞争和权限边界；没有用仅检查注解或按钮文案的测试代替资金证明。新能力按账户、充值、结算、授权、退款、异常与设置用例拆分，未将钱包塞进原 PayNow Intent 或租户控制器。
