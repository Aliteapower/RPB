2026-10-24，D:\RPB。本轮开发与测试，不提交、不推送、不部署。保留工作区原有改动及未跟踪材料，不读取私密文件。

## New / Changed

- 保留充值与积分统一入口和原手机号／个人码确认顾客流程。办理页只承载当前操作，顶部「查看交易记录」进入对应充值／积分文件夹，并用现有customerQuery预填当前顾客手机号；无手机号时不将姓名当作唯一标识。
- 积分分为填写、核对确认、成功结果三个互斥阶段。核对显示顾客、操作类型、数量和原因／兑换内容；核对阶段不记账，确认按钮明确写增加／扣减／兑换。成功不追加历史列表，只显示本笔变化及详情、继续办理入口。
- 从积分办理页移除原手填UUID的冲正表单、流水和空记录提示；冲正原因与日常加扣分原因分属不同页面。更换顾客、门店或操作类型清空未提交内容，提交期间沿用原busy保护禁止切换顾客。
- 由商户积分交易详情发起独立冲正页`/stores/{storeId}/wallet/points/{entryId}/reverse`；原顾客、编号和数量只读，填写独立原因并勾选核实后确认。已冲正、冲正记录、非积分、未完成及无权限不显示入口／不允许提交。顾客端没有冲正入口。
- 冲正成功进入新冲正交易详情，原交易和关联记录保留。停用状态下处理原交易的冲正能力沿用原权限规则。
- 充值核实页保留金额、活动本金赠送、现金凭据选填、实际收款确认及取消；将处理事件／关联历史由内联展示改为「查看本笔记录」独立页面。记录页返回保留充值／积分分类和既有筛选。
- 修正积分办理页转去记录查询时可能自动调用资金账户选择／开户的问题。记录查询及独立冲正不会触发该自动资金开户路径。

## 模块与接口审查

WalletPoints负责当前办理及核对／结果；WalletPointsReversal负责单笔冲正；WalletPointsReversalAction只负责有权限的原记录入口；pointsOperations提供可冲正判定和记录链接。继续使用usePoints及现有资金、积分、查询模块，不实现第二套账本。

后台API、DTO、数据库、迁移、权限、环境变量、依赖均未修改。冲正仍调用原points/entries/{id}/reverse，携带原积分账户当前版本、独立原因及原幂等键。原交易查询仍受租户、门店和顾客权限约束；前端显示判断不取代后台校验。原扫码付款／兑换、营销单档充值、本金赠送分摊、退款、现金收据选填及实际收款确认逻辑保留。

Code Review结论：APPROVE，无未解决P0／P1问题。冲正入口组件仅在商户积分详情挂载，避免影响消费、退款及历史只读回退；原记录及冲正关联不覆盖历史。原有未涉及的组件改动继续保留。
