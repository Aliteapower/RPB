# 无需选客的商户出码审查

## Scope
D:\RPB，本轮开发测试，不提交／推送／部署。商户直接定金额或积分数量并出码；顾客扫码后明确确认，由自身会话识别付款人。无人工查顾客阶段。

## API Review Report
新merchant-orders接口及WM码契约见docs/api/2026-10-24-wallet-unbound-merchant-order.md。Create与Confirm严格DTO拒绝customerId、accountId等未知字段。服务端租户／门店／钱包计划、员工业务权限及AppGate检查；顾客仅本人的资金／积分。GET与POST精确本地放行，保留同源请求头、跨站保护和稳定错误映射。

读取或扫码只预览、不绑定顾客。首次成功确认后绑定付款人；请求行锁覆盖资金／积分调用和完成关联；同时两顾客最多一人成功，其他人不可读取已完成结果。同人重试关联同一账单或积分entry。失败、取消、超时均不生成资金业务或绑定付款人。

## Database Review Report
V066附加wallet_merchant_orders，明确租户、门店、发行计划。money和points的数值列互斥、显式非空且正值／上限约束；只有completed才有付款顾客、完成时间和正确类型业务关联。原表及历史不改；FK同租户，散列查找、门店时间、关联账单／积分entry有索引／唯一约束。仅存码散列，120秒，刷新旧码不能解析。

未预先创建占位钱包账单或积分流水，避免将无法识别顾客的订单混入真实账本。成功后真实账单／积分entry进入既有统一交易记录；消费说明通过只读查询关联意图表显示，不重复收入。回退应用保留附加表及原业务流水，撤销依原退款／积分冲正，不能回写余额或删历史。

## Module Boundary
MerchantOrderController仅负责会话、scope与DTO；MerchantOrderService负责订单生命周期、幂等及确认事务；Repository负责意图持久化；WalletMerchantMoneyAdapter将已明确确认金额转入既有bill/quote/pay；积分委托原WalletPointsAdapter及loyalty模块。不伪造CurrentActor，不新增余额扣减实现，不重写资金分摊或退款。

原WB/WR已绑定接口和旧详情仍保留，兼容已打开的旧页面；新出码入口只用WM，无需在旧接口上放宽顾客归属。个人钱包码、商户扫个人码、手机号充值积分、营销及积分不抵现金规则不变。
