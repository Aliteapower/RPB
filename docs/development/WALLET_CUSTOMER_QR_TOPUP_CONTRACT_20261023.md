# 顾客钱包码与商户扫码充值

范围：复用钱包模块的二维码、扫码器、收银台和收款确认；支付模块仅作为交互参考，不引入外部支付协议。无数据库迁移。

## API 契约

- 顾客 `POST /api/v1/public/stores/{storeId}/wallet/payment-codes` 的既有请求新增可选 purpose 值 `topup`，签发 60 秒有效的 `WP` 钱包识别码，响应类型仍为 `customer_wallet`。`merchant_charge` 仍签发 `WC` 付款授权码；省略 purpose 保留原行为。
- 商户既有 `POST .../payment-codes/resolve` 请求 `{code,purpose:"topup"}` 使用 `wallet.topup.create` 权限。省略 purpose 保持 `wallet.charge.create`。其他 purpose 返回既有 `WALLET_REQUEST_INVALID` / 400。
- 充值识别可使用有效 WP 或 WC；不消费授权，不生成充值单、账单或流水，不改变余额。WC 只在既有扣款确认时消费。WP 不能作为直接扣款授权。
- 保持 App Gate、营业主体/钱包计划、顾客所有权、租户、门店访问及冻结检查；失效、已绑定、跨租户和不同发行主体二维码沿用现有错误映射。
- 识别请求可重复读取。签发新码沿用旧码失效机制；充值提交和实际收款继续使用现有幂等流程。现金充值收据选填规则不变。
- 没有新增 URL 或放宽本地访问白名单。二维码通过 POST 请求体传输，不写入 URL、日志或本地存储。

## 交互与测试清单

顾客钱包首页增加充值码，码页可切换充值码/付款码。充值码自动显示并可刷新；付款码保留明确授权提示和主动出示。充值码不查询扣款结果。

商户充值页支持扫码和原有搜索，扫码后显示姓名、手机和余额，输入金额后进入既有实际收款确认。扫码充值不得把付款授权留给其他收银页面。

验证：真实 PostgreSQL 的签发、充值专属权限、重复识别无副作用、WP 不可扣款、过期/跨租户/冻结/App Gate；前端目的参数、授权清除、模式和门店切换后的迟到响应、充值码不轮询扣款结果；既有扫码扣款、现金确认回归和前端构建。
