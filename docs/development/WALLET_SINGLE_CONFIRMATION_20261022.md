# 钱包扫码单方确认

## 本轮范围

- 商户扫顾客码：员工核对顾客、金额、预计钱包扣款及待补金额，点击「确认扣款并入账」，成功即更新账单、余额和流水，不再要求顾客二次确认。
- 顾客扫商户账单码：保留本人查看报价、确认钱包支付的现有流程；钱包实扣成功直接入账，商户只读刷新结果，不再确认钱包部分。
- 余额不足扣可用余额，剩余继续待补；现金、PayNow、信用卡仍须实际线下收款后确认，不能把钱包扣款当成已收补款。
- 既有待付款单可以重新扫描新的扣款码，由员工确认原单扣款，不另建单。
- 手工选客和旧版身份码仍只建待付款单。新扣款码使用 WC 前缀，旧 WP 身份码不能升级成扣款授权。
- 开发阶段先实现与测试，不变更真实业务数据。2026-10-22 用户随后明确授权提交部署，结果见 [生产发布记录](WALLET_SINGLE_CONFIRMATION_PRODUCTION_RELEASE_20261022.md)。

## 模块与契约

独立 WalletScanChargeService / WalletScanChargeController 编排员工扣款，复用现有账户、账单、流水、幂等、权限及租户顾客目录。无数据库迁移，无计费及其他产品线行为变更。

### 顾客端

- `POST /api/v1/public/stores/{storeId}/wallet/payment-codes` 新增可选 `purpose:"merchant_charge"`，签发 60 秒 WC 扣款码，返回 type=customer_charge；省略 purpose 仍签发旧 WP 身份码。
- 新 UI 出示码前明确提示「出示即授权收银员核对金额后扣款，无需再次确认」，默认签发 WC；生成和识别码本身不扣款。
- `POST .../payment-codes/status`，正文 code，仅本人可查码绑定的最终账单，返回 `{bill:null|Bill}`。只读查询，即使码已过期或门店到期也可查看原交易结果；不在 URL 或浏览器存储放原始码。已在同主体其他门店使用的码返回对应门店原单。

### 员工端

- `POST /api/v1/stores/{storeId}/wallet/scan-charges`，正文 `accountId, amount, customerCode, expectedAccountVersion, idempotencyKey, billId?, expectedBillVersion?`，返回 `{bill,account}`。
- 同时要求 `wallet.charge.create` 与 `wallet.collection.confirm`、钱包 AppGate 和门店商业有效；复用统一租户、门店、经营主体及有效顾客资料。
- amount 为账单总额；已有账单须账户、总额、版本一致，未关闭、未应用钱包且仍有应付。账户版本变化返回 409 WALLET_QUOTE_STALE，须员工重新核对。
- 同一事务按账户 → 已有账单 → 付款码顺序加锁，校验 WC 未用且未到期，然后才创建新单或绑定原单，扣可用余额、写唯一流水、更新支付状态、审计和幂等快照。锁后用当前时间再次检查，不允许排队等待期间过期。
- 同键同参重试返回原结果，即使码随后过期；同键异参 409 WALLET_IDEMPOTENCY_CONFLICT。不同键重复扫码拒绝，不建残单；旧 WP 码 400 WALLET_REQUEST_INVALID。
- 前端在内存保存本次已核对的账户/账单版本；网络丢响应时保持原参数及幂等键，后台余额轮询不能把重试变成另一条命令。确定的 4xx 拒绝后允许重新核对；刷新页面后从账单历史查询原交易，不保存原始码到浏览器存储。
- 403 适用于权限、租户/门店商业拒绝；404 适用于不可见账户、其他顾客/主体码；409 WALLET_AUTHORIZATION_EXPIRED 适用于有效格式的已过期码，409 WALLET_CONFLICT 适用于已绑定码或已处理账单。任何失败回滚全部资金和账单操作。

## 审查与风险

- API：独立控制器仅做身份和 DTO 转交，命令服务强制创建/确认双权限及门店 AppGate；状态查询限本人，不接受客户端租户或顾客声明。未知本地路由保持拒绝，新增方法只放行两个明确 POST。
- 数据库：无迁移，复用 payment_codes 的唯一 hash 与 tenant、bill 约束、账户行锁、命令 advisory lock 和原流水唯一性。新查询按 tenant 限定，读取原单前先确认账户归属。同主体多店共用账户，其他主体不能扣款。
- 兼容：旧 /bills、WP 身份码、顾客 /quote 与 /pay 保留；不修改定价、商业订阅、统一顾客维护、PayNow 收款配置和其他产品业务。
- 资金：任何失败回滚；原单实扣和线下补付分别记录。服务端成功快照支持过期后重放，前端丢响应重试保留核对版本。付款码不进日志、URL 或持久化存储。
- 发现并修复：Vue 数值输入导致字符串解析失败，补了数值输入测试；旧路由源检查遗漏已有模块路由，改为检查主路由实际导入并挂载的钱包模块，没有修改业务路由。
- 发布风险：需前后端配套发布并刷新旧标签页。旧前端生成 WP 仍走本人确认；只有新页面明确出示 WC 才允许员工确认扣款。
- 回退：后续如需撤回，应回到原 WP/顾客确认流程；保留所有已成功账单和流水，不能回滚资金数据。WC 最长 60 秒失效，旧版本不会把 WC 当 WP 绑定或再扣款。
- 开发验收时未提交、推送或部署；后续按用户明确授权执行发布。原有未跟踪验收文档及 rpb信息.txt 始终保留。
