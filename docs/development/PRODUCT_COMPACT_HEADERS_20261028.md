# 存酒、卡权益和日记账紧凑抬头

2026-10-28，D:\RPB。用户要求按已上线钱包样式统一三组页面页头，电脑/手机验收通过后提交部署。本轮明确授权包含提交、推送和生产发布。

## 方案与范围

- 当前存酒路由使用独立商户/顾客组件；采用无业务状态的公共 ProductPageHeader，集中返回、标题、店名、切店、设置、刷新和语言切换。多店选择后直接进入原存酒路径，沿用 home.stores 授权列表，不再重复展示当前店名。非路由入口的兼容 WineStoragePage 不改。
- 次数卡已嵌入钱包商户/顾客外壳，继续使用既有 WalletPageHeader；按卡路由显示“持卡与核销”或“我的卡”，移除子页重复标题及刷新，保留功能开关、设置、目录、顾客扫码和业务操作。
- 日记账保留侧栏导航、权限和离页保存保护；自定义店名/英文名/Logo 从侧栏移至顶部，只展示一次。顶栏保留当前员工和币种，单店隐藏切店标签，多店保留切换。重复同名去重，差异化品牌文字保留。
- 桌面横排、600px 以下标题与操作分两行；长店名最多两行并保留完整 title 提示。日记账 760px 以下先页头、再导航、再业务内容；不更改记账规则或独立的本地版产品。
- 采用公共展示组件，业务页面仍负责加载、权限和操作。未将账本或存酒业务耦合到钱包业务组件，未扩大 API、数据库或模块业务边界。

## 验证清单与证据

- 新增公共组件测试：标题、店名、返回路径、完整名称提示、刷新禁用、操作插槽、卡路由标题、自定义日记账品牌和 Logo、同名去重、员工/币种、单店隐藏。
- 存酒回归按 aria-label 定位图标刷新；语言选择不计入业务标签的活动数量。新增真实组件切店交互，验证当前店名只出现一次，切店仍进入原存酒路径。
- 初次新增测试在公共组件缺失时失败，接入后通过。扩展测试发现旧断言仅按按钮文字及全部 aria-pressed 计数，已按新语义定位更新；不改业务断言。
- 干净源码副本的首轮钱包/卡/寄存/产品历史/日记账组合测试 377 项通过；新增切店用例后存酒专项 79 项通过。最终组合 378 项全部通过。
- Vue 类型检查与 Vite 构建通过；后续仅修正日记账手机 CSS 留白和补测，发布前再次构建。
- 实际展示组件本地浏览器预览：存酒商户/顾客、卡商户/顾客、日记账，共 25 个角色/宽度组合；宽度 320/375/601/760/1440px 均无横向溢出。另查 320px 英文长店名场景。修正日记账移动布局的 flex 自动 margin 留白。
- 预览使用虚构展示资料，不创建认证会话或业务交易；不冒充登录整页、真实多店业务或手机硬件验收。生产使用既有正常登录页另行补验。

## 审查与生产准备

- ui-review / tdd-review / code-review：职责限于页头和展示外壳，原 API、权限、金额、时区、卡权益、存取酒业务和账本保存流程不变。保留原自定义品牌数据、历史快照、日记账离页 flush 和配置入口。
- 无迁移、权限、依赖、环境变量或后端变更。发布从排除了原有未提交钱包组件及其他材料的干净副本构建，复核原文件哈希。
- 纯前端部署：保留旧资源，先新增资源再原子切换 index 和前端版本标记；后端不重启，数据库不变更。发布前备份，失败恢复旧入口和标记，不覆盖业务数据。
- 风险：手机验收为浏览器 CSS 视口，不等同 iPhone/Android/微信实机；自动化和展示预览不替代实际扫码、存取酒、收款或账本写入实测。本轮无此类业务规则变更。
- Production readiness：在最终构建、代码核对和部署预检通过的前提下 GO；发布结果和线上检查另行记录。
