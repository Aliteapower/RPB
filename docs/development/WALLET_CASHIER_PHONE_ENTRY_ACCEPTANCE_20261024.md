# 收银台业务页签与手机号办理验收

2026-10-24，D:\RPB；基线 1a40997e，线上前端 52ace1a0。仅开发测试，未提交、推送或部署；原有未提交文件保留。

## 实现

- 蓝色卡片加入消费收款／充值／积分书签式页签，按权限显示。消费仍先输入金额再扫描有效个人码；充值、积分分别进入预选业务的个人码识别流程。
- 下方独立“手机号办理充值与积分”，进入 /wallet/topup?entry=phone；输入完整手机号，查询结果仅展示候选，点击候选并“确认选中顾客”后才显示充值／积分选项。查询和确认选客不记账、不开户；实际选择充值后才沿用现有资金账户准备逻辑。
- 手机号确认使用收银工作区的独立 phoneConfirmedCustomerId，与扫码 identifiedCustomerId、付款凭证分开。外层切换资金／积分 context 会重新挂载页面，确认状态在同门店、同来源下保留；门店或手机号／扫码来源切换时清空。
- 提交过程中禁用换客及业务切换。更换顾客清空确认、账户、操作类型和表单；手机号充值结果的下一位继续回到手机号入口，扫码办理的下一位仍回扫码。
- 原充值、营销、积分、幂等、线下实际收款确认、个人码付款和权限模块复用。手机号不可直接用于消费扣款，不新增金额或积分记账接口。

## API、权限与审查

无 Java、API 合约、数据库迁移或依赖变更。手机号复用 GET /wallet/customers?query=，后端 WalletAccountService.search 沿用当前员工租户、门店和 wallet.view／wallet.points.view 检查。前端只展示手机号匹配候选，不以此替代服务端权限校验。实际业务写操作仍由原服务检查权限及版本。

按 TDD review、code review 及 release-note 检查；新手机号组件仅负责查询、候选核对与选择，收银工作区负责已确认顾客状态，业务操作仍在原充值／积分页。自审未发现阻塞问题。

## 风险与回退

完整手机号按8–15位数字验证，可带国家区号；仍以同租户候选的完整展示和人工确认为准。真实手机触控及相机尚未重测；本地查询与选客不视为真机扫码通过。前端以条件入口区分来源，未增加短信验证，消费扣款仍要求有效个人扫码授权。

回退时仅恢复本轮收银首页、手机号组件、页面编排、工作区选择状态、文案样式及对应测试；无数据库回写。不回滚其他已有改动。无关产品线未改动。
