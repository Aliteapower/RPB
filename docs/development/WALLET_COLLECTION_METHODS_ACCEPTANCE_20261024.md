## 用户操作与实现

入口：商户钱包「更多 → 钱包设置 → 收款科目」（原收款方式设置地址 `/stores/{storeId}/wallet/settings/channels`）。管理员可新增、改名、调整顺序及移除科目。至少保留一项、最多 30 项，名称 1–60 字且不重复。

默认沿用原现金、PayNow、信用卡。可新增银行转账、支票等名称，选择现金、PayNow、刷卡或其他线下收款作为底层核实类型；类型保存后固定，换类型应新建科目。名称是商户录入的业务内容，不自动翻译。

- 同一租户、同一钱包发行主体的门店共享配置；不同发行主体不会共用科目。仅租户管理员且拥有 wallet.settings.manage、当前门店权限并通过 AppGate 才能维护。未开通钱包的门店先复用原 `/program` 接入，再显示发行主体已有科目，防止开通时覆盖相邻门店配置。
- 新建独立 collectionmethods 模块处理规范化、配置编排、持久化和 API；前端共享 collectionMethods 展示适配。沿用钱包计划、权限、幂等、审计和实际收款模块。
- 商户充值、顾客自助申请、活动档位与普通充值、线下补款都从后端取得科目；不是前端拼出固定三项。仍为选定档位后直接确定充值，不增加获取报价步骤。
- 删除只从新交易可选项移除，标签仍保留供历史和异常实收处理。充值报价保存名称与计划版本，配置变化使新报价失效；充值单、实收及退款展示保存时的名称，不随改名覆盖。
- 现金类充值仍可不填收据；PayNow 类必须配置并核对既有收款账户；刷卡与其他线下收款要求相应账户及凭证。仍需实际收款确认，不接入新的在线自动支付。
- 相同底层类型的两个别名不能复用同一账户和收据绕过重复入账保护。异常实收可以使用原已停用科目，也可登记实际不同科目，但不会记成原计划科目名称或自动增加余额。
- 对账继续按底层现金、PayNow、刷卡分类，增加其他线下充值统计；明细与退款保留具体科目名称。金额、赠送和积分的原规则不变。
