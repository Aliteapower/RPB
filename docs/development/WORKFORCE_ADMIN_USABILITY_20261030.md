# 入口、核准说明、每日人数与假期管理

2026-10-30，D:\RPB。本轮本地实现，不提交、推送或部署。保留前轮排班资格修复及其他既有工作。

## 确定范围与模块设计

1. 常用入口按代码自有产品入口清单汇总，补酒水寄存顾客/员工入口、考勤薪资及打卡/管理入口。仍按当前门店商业授权筛选，员工和管理链接仍需登录和原权限。二维码继续使用统一租户名称，不把产品开通等同员工授权。
2. 新增独立租户级“判定说明”字典：按迟到、早退、休息不足、休息超时、缺卡及通用分类，管理员维护，门店管理者选用。每项支持文本、启停及乐观版本。选用只复制文本到本次核准，仍可手写或留空；判定结果仍必须明确选择，工时与来源校验不放宽。核准记录保存文本快照，不引用可变字典。总审核意见同样可空。
3. 用户确认每日总人数按员工去重，同时列出各班次人数。按营业日期，跨日不重复计数；按当前门店及岗位/姓名过滤，覆盖全量匹配员工，不受分页影响。只有scheduled且未删除记录计数。
4. 管理中把请假类型、年度公共假期、考勤日历、休息考勤规则分别展示。日历以查看已保存结果为主，店休与调休按任务独立展开；新增/编辑与已保存列表分开。年度公共假期清楚显示已保存及草稿，载入模板/复制只改草稿，显式保存后生效。沿用既有权限、路由和业务接口。

## API与数据库契约

GET/PUT /api/v1/stores/{storeId}/workforce/review-explanations[/id]：GET需employeeManage，PUT需租户总部管理权限；均先AppGate及门店范围检查。PUT带expectedVersion、code、text、enabled，返回id/code/text/enabled/version。每租户最多100项，文本1–500字；400格式、403权限、409旧版本/冲突。相同版本+相同内容及成功后一次重复请求幂等。无硬删除，停用不改变历史。

新增V106独立字典表，主键tenant_id/id、租户外键、分类和长度/版本约束。只存常用文本，无自动业务数据或权限开通。核准说明null归一为空字符串，最大500，原异常结果、来源指纹、本人审批限制和历史快照不变；批量意见同步可空。

排班staffing新增dailyTotals: [{date,people}]，与shifts/days共用同一SQL范围，people=count(distinct employee_id)。不按分班人数相加，也不从当前页推算。既有字段兼容保留。
