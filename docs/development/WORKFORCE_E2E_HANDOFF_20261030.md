## 升级验收顺序

核对迁移成功及应用健康 → 确认租户/公司/门店权限 → 长期方案/规则完整性 → 自由员工全额与普通员工异常 → 生成及增量/全量金额对照 → 批量部分成功及恢复 → 发布后的本人隐私 → 付款登记幂等与超付阻断 → 冻结快照不变 → 门店停用/恢复计费及历史事件。正式账单以商业事件和付款证据核对，不能把当前活跃项目汇总当历史实收。

真实数据升级前补查已有停用门店的订阅汇总是否存在历史不一致，单独生成核对清单；本轮未修改现有环境或追溯改写历史账单。

## 回退原则与步骤

1. 发现故障先暂停工资和相关配置写入，保留在途命令ID、日志、版本、迁移状态及故障样本，防止重复确认或付款。实际暂停方式由发布环境现有维护机制落实，不在此假设一个不存在的开关。
2. 仅页面展示问题优先回退前端到先前已验证产物，保留数据库及后端。当前展示修复不改变任何已存工资金额。
3. 后端回退必须选择支持当前个人方案、自由考勤及快照格式的已验证版本。旧计薪器可能误解长期自动方案/自由规则，不能在恢复旧包后直接继续计薪；不兼容时继续保持工资维护窗口。
4. 不自动执行DROP TABLE、删除命令回执、收窄动作约束或重写工资JSON来“降级”。V104/V105新增表和证据保留；若确需恢复数据库，应在明确停写和恢复范围后使用经演练的完整备份，并核对备份点之后的付款/操作，不能只恢复工资表造成账实不一致。
5. 回退后重验权限、冻结工资哈希、付款条数/余额与幂等回执，再恢复写入；恢复和发版同样需要明确授权。
