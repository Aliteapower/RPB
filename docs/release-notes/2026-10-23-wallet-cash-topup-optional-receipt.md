# Release Notes

## Version / Date
2026-10-23，D:\RPB，现金充值收据选填。用户已授权提交部署，结果见 [发布记录](../development/WALLET_CASH_RECEIPT_PRODUCTION_RELEASE_20261023.md)。

## New / Changed / Fixed
- 普通现金充值的收据编号改为选填；勾选“我已实际收到现金并核实充值金额”后可直接确认入账。
- 服务端为空值／空白编号生成按充值单稳定关联的 `CASH-TOPUP-{topupId}` 内部收款编号，用于原单追溯及数据库唯一性；填写的现金收据保留原校验。
- PayNow、信用卡、账单补付和异常收款仍必须填写收款凭证，不扩大本轮范围。

## Migration
无需迁移。沿用原有收款记录非空及唯一约束，不重写历史记录。

## Permission
员工收款确认权限、租户／门店隔离、实际收款勾选、金额核对、终端要求、审计及资金幂等均保持。

## Validation / Review
API 契约已同步。后端先用回归复现无收据被拒绝，再完成修改；新增单元测试覆盖空值／空白编号、稳定内部编号、保留手填编号、其他渠道／用例仍必填，真实 PostgreSQL 覆盖空编号充值及同键／新键重复确认只入账一次、两张现金充值单编号独立。

前端真实 Vue 交互覆盖选填、实际收款勾选、忙碌禁用、其他渠道／用例必填，并回归丢响应幂等重试；生产构建通过。完整结果见本地 `target/wallet-cash-receipt-verified.log`、`target/wallet-cash-ui-verified.log`、`target/wallet-cash-build.log` 和 surefire 报告。

最终结果：后端 57 项通过（含真实 pointer PostgreSQL 随机隔离 schema 的 48 项资金回归），前端 5 项通过，0 失败；Vue 类型检查和 Vite 生产构建通过，git diff --check 无内容格式错误。未新增迁移或改动真实业务数据。

代码审查：范围仅收款校验和表单，控制器及仓储接口未改，未变更资金事务或权限；内部编号只在普通现金充值缺少编号时生成，异常实收不使用此规则。无待修复 P0/P1。

## Risk
无纸质编号时，以充值单和系统内部收款编号追溯；仍需收银员实际收款后勾选确认。本轮未操作线上资金或部署。

## Rollback Notes
回退本轮前后端代码即可恢复现金编号必填；已生成的内部编号及资金记录保留，不执行数据删除或数据库回滚。
