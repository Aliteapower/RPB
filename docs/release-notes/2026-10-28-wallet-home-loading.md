# 钱包首页持续加载与入口失效修复

2026-10-28，D:\RPB。本地完成，未提交、未部署；保留上一轮卡业务记录顾客姓名显示改动及原有无关工作。

## 排查与根因

用户提供的线上 URL：`https://20000000.booking.yumstone.sg/stores/20000000-0000-0000-0000-000000000983/wallet`。经用户授权，在其已登录的 Chrome 标签确认首页显示“加载中”；点击“充值”后 URL 未改变，刷新后仍出现该状态。未输入付款资料、扫描码或执行交易。

WalletStaffHome 根据钱包 context 和权限计算自动跳转目标。cashierActions 每次返回新对象；原 watch 直接观察目标对象。钱包每五秒刷新 context，路由守卫又会刷新权限，都会生成内容相同的新目标对象，引发重复 router.replace。尚未完成的跳转被后来的跳转取消；缓慢网络/权限校验下会一直停留在首页。原代码也没有处理路由拒绝、异步页面资源加载失败或长时间未完成后的恢复状态。

使用真实 Vue Router 的内存路由与可控慢守卫复现：原代码同一目标产生 4 次跳转（应为 1 次）；路由拒绝/异常后仍显示 Loading，异常 Promise 未处理。

## 修改与审查

- 以目标路径及 query 内容生成稳定标识，仅目标发生实质变化才启动自动跳转。相同 context、权限刷新不会取消正在进行的跳转。
- 处理跳转被拒绝与异常，显示中文/英文提示和手动重试按钮。
- 等待十五秒仍未完成时显示恢复入口。该计时仅更新导航 UI，不提交交易、不放宽权限；手动重试可取代旧导航。
- 版本号隔离旧尝试，目标改变和组件卸载时清理计时；用户手动切换充值等入口后，旧自动跳转不会把页面送回消费页。

仅修改 WalletStaffHome、钱包中英文提示及新增回归测试。原路由守卫、门店权限、共享 workspace、收款/充值/退款命令与幂等机制不变，无 API、迁移或运行配置变化。UI 继续使用原 wallet-empty/wallet-error 样式，无布局重构。
