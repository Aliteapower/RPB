# 存酒顾客/商户入口及界面调整

日期：2026-10-25。状态：本地实现与验证，未提交、未部署。

## 变更

- 顾客钱包入口及页面名称为“我的存酒卡”；商户收银台入口及页面名称为“酒水寄存管理”，增加明确的顾客端/商户端标识，中英文同步。
- 两个已有 URL 分别绑定 `WineStorageCustomerPage` 和 `WineStorageStaffPage`；角色固定，外部透传属性不能切换角色。共用寄存工作区、表单和交易规则，避免复制交易逻辑。
- 顾客仅调用 `/api/v1/public/stores/{store}/wine-storage`，商户仅调用 `/api/v1/stores/{store}/wine-storage`。仍由原后端分别认证及授权，没有修改 API、商业门禁、权限授予或数据库。
- 顾客申请/领取与商户收存/交付/规则管理继续分别展示；即使顾客响应误含商户权限，顾客页仍不显示商户收存和规则编辑操作。
- 复用共享 commerce 样式，寄存页采用与卡与权益一致的白色卡片、圆角、边框、主次按钮与选中页签；门店、筛选及内容分区，补充空记录展示及手机布局。
- 商户“返回钱包”指向收银台首页；顾客返回自己的钱包。两个入口不互相跳转。

## 验证

- 页面渲染、角色固定及原寄存/卡扫码恢复/目录边界组合回归：13 项通过。
- 钱包收银台及相邻操作针对性回归：14 项通过。
- 最终 `npm run build` 通过，包含 TypeScript/Vue 检查与 Vite 生产构建。
- 两项角色标题/返回/样式关联测试先失败后通过；透传角色属性的测试先揭示组件默认属性透传风险，再用显式禁止透传修复，复测通过。
- 本地环回只读模拟 API，使用虚构店铺和寄存物品，对实际构建前端做浏览器验证：商户桌面布局、顾客独立页面、390px 手机宽度、中英文布局均已检查；手机无横向溢出。
- 模拟服务不连接后端或数据库，所有写请求为 405；不把样式预览视为真实后端业务验收。检查后关闭任务预览服务和页签，恢复浏览器尺寸。
- 原先记录的 4 项顾客首页测试基线失败未在本次扩大修复范围；没有声称前端全量测试通过。

## 审查及回退

前端自审未发现本次改动带来的 API、交易或权限隔离问题。业务行为继续复用原服务，预订、排队、到店、座位、清洁未修改。回退时仅撤销这次角色入口绑定、文案和样式补丁，不覆盖其他已有工作区文件，不回退交易记录或数据库。
