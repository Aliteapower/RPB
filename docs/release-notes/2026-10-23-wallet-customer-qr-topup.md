# 顾客钱包码与扫码充值（2026-10-23）

## 新增与调整

- 顾客首页增加“出示充值码”；码页可切换充值码与付款码。充值码进入页面即显示，60 秒有效，可手动刷新。
- 商户收银台增加“扫码充值”，充值页同时保留顾客搜索。扫码后核对顾客、金额和收款方式，再沿用现有实际收款确认与结果页。
- 充值扫码不扣款、不入账，也不保留扫码取得的扣款授权。付款码继续沿用既有商户确认扣款流程。
- 现金充值收据选填规则保持有效。没有调整预约、排队、入座、清洁或其他产品线业务。

## API、权限与迁移

既有签码、识别请求增加可选 `purpose: topup`；充值识别使用 `wallet.topup.create`，省略用途保持原扣款识别权限。继续执行 App Gate、租户、门店和发行主体限制，使用既有不透明短期码。无新权限项、URL、依赖、配置或数据库迁移。

## 验证与风险

数据库验证使用 D:\RPB 的 `target/local-postgres-current.txt` 指向的 PostgreSQL，测试使用独立临时 schema。覆盖重复充值幂等、扫码无财务副作用、识别不消费付款码、充值码不能直接扣款，以及权限、失效、冻结、跨租户/发行主体隔离。前端验证模式切换、迟到响应隔离和原扫码/现金流程。

摄像头仍需 HTTPS 和设备授权，保留二维码图片识别及原搜索入口。手机实机摄像头验收尚未执行。签发新码沿用旧码失效规则；过期或被替换时重新生成即可。

本轮验证通过：66 项后端测试（其中 50 项真实 PostgreSQL）、38 项前端测试（含 2 项实际 Vue 页面组件测试），以及 `npm run build` 的类型检查和生产构建。

## 发布与回退

用户已授权“提交部署”，本次前后端一起更新，实际结果另记生产发布报告。回退时恢复发布前的前后端制品，无数据库回退步骤，既有资金和业务记录保持原流程。
