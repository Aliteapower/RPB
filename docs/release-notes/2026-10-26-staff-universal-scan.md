# 租户端通用扫一扫（2026-10-26）

## 使用方式

租户员工首页及钱包收银台增加“扫一扫”，统一进入 `/stores/:storeId/scan`。沿用已有相机、相册识别和粘贴入口。

- 顾客卡授权码 CA：直接调用原卡授权核销，次数卡、期限卡及集章相关请求仍由卡模块判定数量、日期、额度与具体权限。
- 取酒码 WS：直接调用原扫码取酒核销，按顾客授权的商品和瓶数整批办理；商户来源码、取消、过期或已经使用的码仍由后端拒绝。
- 个人顾客码 WI：根据原权限识别顾客，提供消费、充值/积分、卡业务、存酒和取酒操作。消费填写金额后才提交，超限需顾客确认的原账单流程保持不变。纯收款岗无顾客查询权限时，仅识别码格式，最终消费仍由服务端校验。
- 旧 WP / WC 码兼容识别。消费继续要求当前个人钱包码 WI，不把旧识别能力升级为扣款授权。顾客识别仍使用现有钱包/卡权限；没有新增全局顾客查询权限，只有酒水权限的员工可以直接扫描 WS。
- 顾客交接到充值、卡业务或存取酒时无需再扫描/搜索。新存酒仍须原实物、照片、规则及商户确认，不能扫描身份码就自动生成收存事实。

## 边界与恢复

共享扫码分类器仅校验类型、长度和卡链接的同源/当前门店路径，不打开任意扫码网址。所有实际请求仍使用当前门店 API 和原登录身份；服务端继续负责租户、门店、权限、App Gate、期限、数量及防重放。

`staff-scan` 模块只拥有通用入口、结果展示和交接编排；不新增资金、卡权益或寄存领域规则。卡、酒水继续调用原 `cardApi` / `storageApi`，消费复用 `createPersonalChargeAttempt` 和原账单详情。分类器采用项目已有 `.mjs` + 类型声明模式，同时兼容 Vite 与 Node 原生扫码回归。无后端接口、Java类、迁移、权限、依赖或运行配置变化；不改变预约、排队、入座及清台流程。

跨页交接仅保留一次30秒内存数据，按门店、操作账号和目标模块校验，不把令牌放入URL；目标模块重新调用原身份或顾客接口核对。原模块幂等与恢复数据保持现状。新通用核销增加原操作账号标记，未知结果先查原操作，期间禁止继续扫新码；其他入口的历史待处理操作提示回原入口恢复。

个人钱包消费丢失响应时锁定金额和说明，查原幂等结果，不自动再次扣款。明确返回未提交时解释结果，等待再次主动办理。切账号/门店或卸载页面后忽略旧结果；顾客身份交接亦有账号/门店保护。

## 风险与回退

本轮仅本地实现，未提交、推送或部署。未启动本地后端、未执行SQL、未创建生产会话或实际存取酒/资金/卡核销。实机相机、微信/iPhone/Android及生产端到端核销仍待设备与部署验收。

回退本轮入口、路由、分类器和交接集成即可回到原独立扫码入口；数据库和原交易规则无需回滚。保留各模块未确定操作的原恢复记录，不覆盖业务数据。
