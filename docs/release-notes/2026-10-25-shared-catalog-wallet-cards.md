# 共享产品目录与钱包卡业务变更说明

日期：2026-10-25。状态：功能提交 `9835201d` 已推送并部署；产品目录、卡业务及原钱包生产验证通过。详见 [生产发布记录](../development/CATALOG_CARDS_PRODUCTION_RELEASE_20261025.md)。

## 新增

- 独立 `catalog` 后端与产品管理前端：分类、中英文资料、实物/服务、单位、图片地址、精确金额、含税/未含税、税务类别和税率。
- 租户级产品资料与全局生命周期；门店级价格、渠道投放和启停。租户管理员维护共享资料，门店管理员只能调整授权门店的投放。
- 独立 `cards` 模块：免费领卡、消费/签到来源集次、循环达标奖励、奖励持有与核销、付费次数卡、每日周期额度及组合限制。
- 顾客卡包与购卡申请、员工售卡确认、集次与核销、商户出码/顾客扫码、顾客具体授权码/商户扫码、原单冲正及未使用卡退款。
- 购卡实收、退款、集次、奖励与核销记录分别保存；支持历史游标、顾客筛选和卡业务统计。
- 确认授权冻结卡片、数量及业务日；日额度不累计，跨日使用必须重新确认。未使用日额度可以从规则与日用量推导统计，不当作消费。
- 已实际收款但原报价无法正常发卡时，经理可以登记异常实收并按原渠道退款，保留原单线索。

## 调整

- 钱包仅提供入口、身份/AppGate 和支付适配，卡业务不写储值或积分账户。
- 产品目录前端与卡业务前端没有反向依赖，共用通用 HTTP、格式化与样式能力。
- 管理后台新增独立产品入口；钱包更多页增加产品/卡业务入口；顾客首页增加卡包。
- 收款科目沿现有钱包配置，支持自定义科目；停用科目不能用于新购卡，原单异常收款恢复单独受控。
- 钱包和购卡复用外部实收凭证登记，避免同一凭证跨业务重复入账。

## 数据库

新增 V071–V076，未改动原历史迁移：

1. V071：共享分类、产品、门店价格/渠道、幂等及审计；管理角色权限补齐。
2. V072：卡方案、持卡、日用量、奖励、业务意图、购卡、实收关联、流水、命令及审计。
3. V073：共享线下收款凭证占用；历史钱包凭证归档登记，不改其金额或原分录。自定义科目按结算类型统一去重。
4. V074：异常实收及异常退款状态。
5. V075：授权业务日、集次奖励轮次和单调流水序号。
6. V076：门店独立上下架及投放版本。

`name_zh/name_en` 为本期两种语言的业务资料，不使用系统文案表保存用户产品名称。跨模块查询接口隔离这一存储细节，未来增加语言时另行扩展。

## 权限与隔离

- `catalog.view/manage/publish`：查看、门店投放维护、共享资料及生命周期管理；共享写入额外要求 tenant_admin。
- `wallet.cards.view/manage/sell/stamp/redeem/reverse/refund`：分别约束查看、配置、售卡、集次、扣次、冲正、退款。
- 不默认给普通员工授予新权限；原租户/门店管理角色由迁移及账户建立逻辑补齐相应权限。
- 新交易验证钱包 AppGate、门店开关与卡开关；历史、原单冲正和退款保留受控入口。
- 新增目录及卡 API 的同源保护与本地安全入口；未拓宽其他业务路径。

## 首版限制与风险

- 本店使用、SGD、线下收款后确认发卡；不提供钱包余额购卡、跨店卡、自动续费、转赠或提现。
- 已使用卡不开放退款；不能因为产品下架而取消已有持卡权益。
- 寄存酒、积分商城、自助购物只建立目录复用边界，不在本次实现其交易业务。
- 浏览器及真实 API 已验收；摄像头硬件、微信/iPhone 实机能力需要单独验收，不能用二维码格式/接口测试代替。
- 首版无实物库存预占；后续商城/自助购物接入库存时需单独模块，不各自维护一份库存。

## 回退

已完成备份、迁移演练及生产发布，备份位置见生产发布记录。发生问题时关闭对应门店的卡开关，保留历史读取和原单处理。回退前端/后端代码时保留新增表、已确认实收和历史分录，不删除资产、不回滚已入账事实。共享收据登记需要和钱包收款代码配套回退，不能只绕过一侧。
