# 顾客存酒与钱包入口隔离（2026-11-02）

## 变化

- 存酒顾客页的返回钱包按钮仅在本租户、本门店钱包AppGate商业有效时出现，未返回状态时默认隐藏，复用原存酒home刷新。
- 钱包首页对从未开通且无本人历史钱包账户的情况返回403/WALLET_PRODUCT_UNAVAILABLE。已开通过但关闭/到期及本人旧账户仍沿用原只读查询；普通首页只显示不可用说明与显式历史入口，不加载余额、积分、卡权益、充值等业务子页，避免空钱包和积分报错。
- 顾客注册/激活/密码恢复独立保留。来自存酒的共享注册会保留当前门店返回目标，登录后回存酒；只接受白名单中的当前门店公开路径，不允许外部或跨店跳转。

## 接口与数据

存酒home追加walletEnabled布尔字段，钱包me新增上述未开通拒绝情形，见 `docs/api/2026-11-02-customer-product-entry-isolation.md`。旧服务无字段时前端不展示钱包返回。未新增迁移、写接口、权限、订阅或资金操作。历史接口、退款/原单善后授权不改，业务事实不删除。

## 验证与审查

- 前端276项关联行为测试通过，覆盖入口开关、同店恢复与关闭、中英文、跨租户会话、注册返回目标、历史视图、钱包交易和积分、存酒及顾客密码流程。关闭/到期只限制普通首页，既有卡权益和原单子页沿用各自的原控制，不扩大为整棵历史路由禁用；从未开通的不可用标记仍阻断业务子页。新增该边界失败复现及通过测试。
- 后端156项关联测试通过，包含钱包产品门禁、匿名与越权、实际PostgreSQL的钱包账本/交易/历史、存酒流程与范围隔离。运行前读取本工作区指针，使用61644/postgres的随机自有测试schema，没有更改真实订阅。
- 缺陷用例有修改前失败和修改后通过证据；字段由后端AppGate提供，界面不使用租户名字或代码特例，不用存酒权限替代钱包授权。
- 代码/API审查：先验顾客身份和门店，再查询其历史账户及商业资格；缺失身份仍401，跨租户范围沿用原错误。注册模块不依赖钱包商业许可，返回路径受限；页面复用共用页头和wallet-card样式，无自定义页面宽度。
- 构建、浏览器与生产结果以同日后续部署记录为准；工作区原有9个无关业务文件改动不纳入发布。
