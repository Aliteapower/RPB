# 顾客存酒按任务分区

日期：2026-10-25。状态：本地实现及验证，未提交、未部署。

## 顾客流程

- 默认“我要存酒”：直接列出酒品，支持搜索、选择或填写未找到的酒名，再填写瓶数、瓶况、来源、实物照片及备注；无需再次选择顾客或填写顾客编号。提交后提示等待门店核实收存，并进入申请记录。
- “我要取酒”：只列出未过期、仍有可领数量的酒品；没有选择、数量为零/负数/小数、超出余量或已失效时不能继续。先核对领取清单，再生成取酒码；不把生成授权码当作实物交付或扣减完成。
- 等待期间酒品到期或被刷新为不可领取时，清除对应已选项并退出原确认清单，避免隐藏的无效选择阻塞操作。
- “我的记录”：单独查看寄存申请、取酒记录、已结束的寄存；保留原申请取消、商户码授权、领取取消及再次寄存能力。
- 三项任务各自显示相关组件，支持 URL `view=deposit|withdraw|records`；不再把商户的物品搜索、顾客分组、规则维护、操作审计堆在顾客页。
- 商户已出码的扫码确认入口折叠在取酒任务中，保存规则放在存酒须知中。当前门店仅展示名称，不要求顾客再次选择自己。

## 模块与身份

- 独立顾客页面及工作区组合逻辑位于 `WineStorageCustomerPage.vue`、`customer/useCustomerStorage.ts`；领取选择、记录、文案分别维护，寄存表单继续复用原实物照片组件。
- 顾客始终调用原 `/api/v1/public/stores/{store}/wine-storage`；申请和领取 payload 不传顾客编号，由后端登录会话确定本人，仍由后端校验持有归属、期限、数量及权限。
- 没有修改 API、数据库、商户交易流程或实物交付规则。没有默认存入、默认交付或在客户端修改寄存数量。
- 保留幂等恢复：结果未确定时阻止新提交，提供查询原提交结果入口；登录失效清除旧持卡/取酒码显示状态；跨店加载使用原请求代次防止旧数据覆盖新页面。
- 再次寄存仍要求新的照片及门店确认，数量限制不超过对应原领取数量。
