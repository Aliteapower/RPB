# 钱包办理流程与统一顾客入口

2026-10-24，用户授权提交部署。

- 充值与积分办理、交易记录、积分冲正分开，积分采用填写、核对、结果步骤；原交易详情发起冲正。
- 商户选活动单档与渠道后直接“确定充值”，内部自动核价，保留实际收款核实后才入账、现金收据选填及原幂等机制。
- 钱包收银台、“更多”、充值与积分页复用租户原顾客管理；手机号无匹配时可进入原新增表单，返回后仍需核对并确认选中顾客。
- 顾客档案、手机号唯一规则与管理权限继续统一，无钱包独立顾客表或写接口。普通收银员权限不扩大。

验证：同一源码状态 153 项钱包前端测试、10 项相关 Java 测试、类型检查和构建通过；隔离 PostgreSQL 与浏览器验证充值单未确认不入账、积分增减和冲正不影响资金、统一顾客新增维护及重复手机号／门店隔离。详见同日三个验收记录。

仅更新前端，不重启后端。无 API、依赖、环境配置、权限或数据库迁移变更；既有付款、营销、充值、退款、积分和其他产品线后台保持原版本。真实手机硬件未验证；已验证本地浏览器移动宽度布局。

发布前须持 RPB 发布锁校验前后端 SHA、旧 index 和 jar 哈希，备份旧前端及数据库并验证 dump 可读。先复制新资源且保留旧资源，再原子切换 index；失败恢复旧 index 与前端版本标记，不恢复数据库覆盖业务数据。

无关改动、既有未跟踪资料与私密文件保留，不纳入提交或制品。发布结果另记生产验证记录。
