# Troubleshooting Report

## Symptom

- 新建租户 `lcd` 的现场取号返回 `QUEUE_GROUP_NOT_FOUND`，消息键为 `walkin.queue.queue_group_not_found`。
- 同一门店的预约到店排队返回相同错误码，消息键为 `reservation.queue_group_not_found`。

## Evidence

- 两个请求均已进入排队业务逻辑并返回业务错误，说明 `reservation_queue` App Gate、租户授权和对应权限校验已经通过；这不是模块未开通导致的拒绝。
- 现场取号与预约到店排队都会按租户、门店和就餐人数查询有效 `queue_groups`，查询不到时抛出 `QUEUE_GROUP_NOT_FOUND`。
- 平台创建租户的默认门店链路和后续新增门店链路此前都只创建门店，没有初始化默认排队分组。
- 现有 Flyway 迁移截至 `V045` 没有为无排队分组的存量门店执行回填。

## Root Cause

- 这是租户/门店初始化缺失的持久化缺陷，不是平台管理员未开通模块。
- 排队业务依赖门店级的默认人数分组，但门店创建流程与存量数据迁移均未保证该前置数据存在。

## Affected Files

- 平台租户和门店创建应用服务。
- Queue 模块的默认排队分组初始化端口、应用服务和 PostgreSQL 适配器。
- Flyway `V046__backfill_default_queue_groups.sql`。
- 平台租户 API 与迁移集成测试。

## Fix Plan

- 在默认门店创建和显式新增门店的现有事务内，统一初始化 `1-2`、`3-4`、`5-6`、`7+` 四个有效排队分组。
- 初始化使用租户与门店双重作用域，并在门店已有任意排队分组历史时保持原配置不变。
- 通过 `V046` 给所有未删除且从未有过排队分组记录的存量门店补齐同一套默认值；不写入 LCD 或任何门店 UUID 的特例。

## Verification

- TDD 红灯确认：新增租户和新增门店 API 成功后，原实现查询到的默认排队分组均为空。
- 修复后相关 Maven 回归共 68 项通过，覆盖租户创建、门店创建、迁移幂等、预约到店排队和现场取号。
- 迁移测试使用真实 PostgreSQL 验证：空配置门店补四组；自定义、停用、软删除分组历史不被覆盖；软删除门店不回填；重复执行不新增记录。
- 指针 PostgreSQL `61644` 上事务式执行 `V046` 后得到四组预期数据，随后回滚，验证夹具计数为 0。
- `npm run build` 通过。

## Remaining Risk

- 生产 LCD 数据只有在部署包含 `V046` 的后端版本并成功执行迁移后才会修复；本次未直接修改生产数据库。
- 如果某门店已有停用、部分配置或软删除的分组历史，迁移会尊重该历史而不自动重建，需要管理员按业务意图处理。
