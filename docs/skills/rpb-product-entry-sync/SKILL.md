# RPB 产品线入口同步

用于RPB产品开通后的入口集成和验收。覆盖管理员、员工与顾客；入口变化服从后端商业状态、身份和权限，不反向修改订阅。本文路径均相对已确认的RPB根目录，当前项目为 `D:/RPB`。

## 先核对拥有者

读当前AGENTS、产品注册目录及相关模块，再按[集成与验收参考](references/integration-and-acceptance.md)定位调用链。新增产品不仅检查管理员侧栏，还要查员工首页/底部导航、钱包快捷入口、顾客首页及子页面。角色不适用的产品明确标注“不适用”，不为顾客制造员工功能。

先记录每个入口的产品key、角色、状态接口、权限、门店范围、普通路由和历史路由。复用已有注册、授权、刷新和历史组件；不再维护一套独立商业状态或产品白名单。代码路径和现有间隔须现场核实，过去发布SHA、schema、端口和通过数量不是当前证据。

## 核心边界

| 情况 | 期望行为 |
| --- | --- |
| 已开通且本店启用、本人有权 | 展示该角色可用的业务入口 |
| 到期/停用/无商业授权 | 隐藏新增业务入口；只按后端允许的历史能力保留历史入口 |
| 恢复有效 | 自动恢复允许的业务入口；不自动打开管理员主动关闭的门店开关 |
| 切店/身份改变 | 先清空旧范围，再读取新范围；旧响应不能覆盖新范围 |
| 目录/入口摘要读取失败 | 清除受影响的入口；业务工作区沿用已有错误策略，权限/归属拒绝时清除旧授权状态，下次有效读取可恢复 |

- 租户授权、门店订阅期间、门店启用/入口可见、账号权限是不同条件。开通或同步产品不扩大员工门店/公司/租户权限，也不扩大顾客数据范围。
- 员工/管理员复用 `/api/me/apps` 的 `apps` 和 `historyApps`。顾客使用自己的身份、产品context/home及记录接口；不能借员工会话或把员工目录授权给顾客。
- 历史可见和业务可用分别处理。不能因产品关闭清空余额、积分、卡权益、工资、付款或旧记录。酒水关闭后有记录才显示的顾客快捷入口是该模块现有规则，不推广为所有产品的统一记录数量判断。
- `history=1` 是显式视图标记，不是后端读写授权。日期、分类、分页、详情、返回、底部导航都要保留既有只读上下文；不要把该标记加入原本不接受它的业务API查询。恢复开通后仍查看历史时，提示“当前只读”，不能误报“产品已关闭”。
- 显式只读视图不因权限齐全而出现新增交易或冲正入口。退款、取消及有效酒水受控领取等原单操作沿用已有独立规则；不自行统一放开或禁用，也不新增商业规则。

## 复用刷新机制

- 员工/管理员优先使用 `useStoreVisibleApps`；顾客/产品摘要复用 `useVisiblePageRefresh`，由模块自己的只读查询提供状态，不将权限判断塞进刷新helper。
- 保留现有频率：当前目录及酒水30秒，顾客钱包5秒。focus、pageshow、恢复可见立即重查；隐藏页不轮询；卸载移除定时器/监听。不要对新产品盲目套用更高频率。
- helper只负责生命周期。调用者负责loading/busy、未确定操作及登录状态，防止同范围慢请求重叠；切店、角色/顾客身份切换和卸载使用generation/request序号隔离旧响应。
- 区分后台只读刷新与业务命令，不能因轮询重放提交、发码或付款。不要用重载页面、重绑组件或新增每产品定时器掩盖缺失的共享刷新。
- 确认缓存不会保留旧商业状态；员工目录已有 `cache: no-store`。不要以静态 `onMounted` 或只watch门店代替同店停留时同步。

## 合成验收与交付

按参考中的矩阵补行为测试，再做本地浏览器/API验证。**复用合成数据，不改真实订阅**；线上只读核查不能变成开通、到期、停用或续费试验。技能本身不授权生产变更。

运行后端、迁移或SQL前读取当前工作区 `target/local-postgres-current.txt`，使用其port、127.0.0.1/postgres、postgres空密码；核对运行环境归属与存活。指针缺失/过期先按项目本地恢复指南修复，不回退系统数据库。旧target脚本须先审计，不能直接重放旧seed/部署脚本。

验收要有实际身份、门店切换、自然到期、历史读取及后端写入拒绝证据。测试代码通过不等于浏览器通过；DOM宽度不等于已保存截图；公网资源哈希不等于线上交互；桌面窄屏不等于实体手机或微信。

完成报告：改动与复用模块、各角色/状态验收结果及证据、实际CSS尺寸、数据保护指纹、未覆盖部分。只按当前会话已有授权提交/推送/部署；不为技能增加固定审批菜单。保留无关工作区改动；若发布，只构建已核实的范围并证明制品对应提交，发布后重新核验当前状态。
