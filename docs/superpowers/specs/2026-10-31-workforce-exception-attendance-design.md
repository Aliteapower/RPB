# 月度异常考勤与四类考勤计薪方式：最终业务版

日期：2026-10-31（Asia/Singapore）。项目：D:/RPB。

状态：已按本次对话确认的业务方向实施本地版本；实际范围和验证以文末第14节及验收记录为准。本文不是生产发布证明。用户已授权写入 Markdown 并继续优化落地；不因此要求重复审批已经确认的业务规则，也不因此获得提交、推送或生产发布授权。

**2026-10-31范围修订：**用户明确说明仍在开发中、无真实用户工资数据，线上与线下旧工资均可删除，按本版直接重建。取消旧工资数据迁移、旧快照解码、旧工资API/默认映射兼容和旧工资不变验收。删除授权已持续有效，无需重复确认；具体对象须先核实归属和依赖，使用精确清单清理。该授权不包含清空整库、其他产品、员工/账号、合同证件、排班打卡、请假及公共审计，也不自动等于新版生产发布授权。新版启用后形成的工资仍须正常审计、确认冻结和纠错。

## 1. 业务目标与已确认决定

采用异常管理：管理员以“员工一行、日期一列、月底合计”核对考勤，员工以本人月历查看每日及当月情况。正常上下班不逐格标注；加班、休息、请假、缺卡、缺勤和待核对事项明确展示。

已确认：

1. 同时支持“打卡核对”和“默认正常、登记例外”。
2. 门店设置默认方式，员工可单独覆盖，按日期生效并保留历史。
3. 原有“自由免考勤”单独保留，不改变原计薪规则。
4. 新增“免打卡按合同计发”，不生成虚拟出勤工时、不要求日常工时核准。
5. “免打卡按合同计发”的加班待遇完全按有效合同约定处理，不能从打卡或排班差额自动推算。
6. 共用月度考勤入口，正常事项减少重复核准，异常与工资来源能够追溯。

下文的解析优先级、状态、数据结构和实施拆分是为落实以上决定提出的工程设计；不将它们伪称为用户逐字段确认。固定周工作安排是推荐来源，不强制替代既有轮班排班。

## 2. 四种方式

| 方式 | 正常依据 | 是否产生考勤工时 | 工资依据 | 加班处理 |
| --- | --- | --- | --- | --- |
| 打卡核对 | 有效排班、实际打卡与休息；正常完整班次由系统判定 | 实际及有效核准工时，分别保留 | 有效个人薪资方案＋有效考勤来源 | 复用日/周规则及同公司跨店合并计算；需人工核对的例外单独办理 |
| 默认正常、登记例外 | 有效工作安排；已结束应出勤日无未决例外时推导正常 | 产生“按安排认定”的工时，明确区别于实打工时 | 标准安排工时＋批准例外＋有效个人薪资方案 | 经批准的额外工作区间进入工时来源，再用同一加班引擎计算 |
| 免打卡按合同计发 | 有效合同计薪条款及适用个人政策 | 不生成出勤或核准工时 | 按合同有效条款计算，处理适用的请假、入离职和批准调整 | 完全按合同：已包含、另计或不适用必须有明确依据；缺失条款不能猜 |
| 自由免考勤 | 保留原实现 | 工时不适用 | 保留原有自由员工固定工资及现有适用条件 | 保留原规则，不自动升级为新合同计薪方式 |

考勤方式与计薪方式（月薪/日薪/时薪）分开。不能仅因切换考勤方式就改变工资金额或个人待遇。合同计薪并不自动限定为月薪；日薪/时薪必须有合同计薪单位依据，不能伪造考勤小时代替。

### 2.1 与已有打卡位置方式的关系

现有 `legacy / onsite / field / home / free` 同时涉及历史兼容、定位、居家地址和自由员工。新增考勤计薪策略独立建模，不把 `default_normal`、`contract` 塞进定位枚举。

- 打卡核对继续使用已批准的现场/外勤/居家组合与原定位校验。
- 默认正常和合同计发不开放日常打卡，不用位置模式拼接特殊含义。
- 无新策略时严格沿用旧行为；旧自由员工不因门店新增默认策略被自动改制。
- 自由员工改制必须有明确的员工策略变更，预览薪资适配风险；保留非工资的工作方式来源。切换前旧测试工资可按授权清理，不要求保留旧工资快照。

### 2.2 生效与继承

解析范围为租户、发薪公司、员工和业务日期，个人覆盖优先于对应任职门店的默认；跨店临时工作不使同一员工同一天自动切换计薪依据。以该日期有效任职主门店确定默认来源，不用浏览页面时选中的门店。

当前 `main_store_id` 是可覆盖的当前字段，不能直接用于回算历史。新增按日期的任职主门店关联；首次显式采用策略时固定来源门店、关联版本与生效日，不无依据补造旧任职历史。主门店变更与策略采用分别留痕：只有显式安排新的策略生效才改制，不因临时跨店或当前主门店字段变化自动换政策。工资从明确的新版本启用日期开始；无需回算或补造被清理期间的工资。

门店默认采用版本化记录；员工采用某个默认时形成明确的生效关联与来源快照，不随以后门店默认变化偷偷改制。新默认变更提供影响预览及批量安排未来生效；个人覆盖保持。员工解除覆盖须显式采用一个当前可用默认，不能删除旧记录实现“继承”。

新策略最早次日生效；不通过回溯改制修改历史。月中变更可以保存未来策略，但未实现同月混合计薪前，相关工资明确阻断并提示按合法分段/差额路径处理，不能按月底策略覆盖整月。

## 3. 管理端月表与员工月历

管理端选择月份、授权门店和岗位/员工筛选；固定姓名列、日期表头和合计列。31天宽表只在表格容器内滚动，复用 WorkforceLayout、wf-panel、wf-table-wrap 和公共操作样式，不私设页面宽度或浮动保存栏。

员工端只看本人，提供手机可读月历及当天详情；管理员手机可以切为员工卡片/单人月历，不要求在320px视口中操作整张31列表。

| 当天情况 | 格内展示 | 核准含义 |
| --- | --- | --- |
| 已结束且依据完整、系统已判定正常 | 留白，提供可访问说明及详情 | 系统有效记录，可追溯，并非缺数据 |
| 已安排休息 | 休 | 不是缺勤；不按周末直接推定 |
| 无有效工作安排 | 未安排 | 不得视为正常、不计默认工时 |
| 尚未到日/班次未结束 | 未到日/进行中，以底色或占位区别 | 不能提前认定出勤 |
| 请假 | 假别＋小时或天数 | 待审与批准分清；已批准不重复审批 |
| 加班 | 加班时数＋待确认/有效状态 | 暂计与已确定分清，不冒充应付金额 |
| 有安排但缺卡 | 缺卡待核对 | 不直接认定旷工 |
| 已核实缺勤 | 缺勤＋时长 | 依据有效决定进入考勤与适用政策 |
| 来源变化/冲突 | 待复核 | 不能留白或消费旧核准 |
| 免打卡按合同计发 | 员工行标明方式，正常日期不逐格铺字 | 工时“不适用”；请假和合同调整仍可见 |
| 自由免考勤 | 员工行标明自由免考勤 | 保留原语义，不标成正常满勤 |

同日允许多个项目，例如上午年假2h、下午正常、另有批准额外工作1h。摘要不能只选一个状态而隐藏其他事实。展示优先级：来源冲突/待处理 → 缺卡/缺勤 → 请假/加班 → 休息 → 正常；详情保留全部项目。

右侧汇总至少有：已确定加班、待确定加班、带薪假、无薪假、缺勤、待处理事项数。天与小时分别标单位；没有有效换算政策时不把半天猜成4小时。未知、真实0和不适用分别显示。正常日留白不等于不保存或不可查询。

## 4. 默认正常的工作依据及例外

支持复用现有有效排班；固定周工作安排作为批量生成/解析正常工作日的来源，需明确工作日、标准时段、休息规则、每日标准净工时、时区和生效期。不为每月使用重复要求配置。缺来源时提示补工作安排，不算满勤。

- 仅有效雇佣期间、有效公司归属、方式已生效且已结束的应出勤区间可认定正常。
- 休息、公众假期、店休、调休与班次覆盖按已有业务关联解析；有冲突则待核对，不静默叠加。
- 默认认定工时标明 `arrangement` 依据；实际打卡时间保持空值，不能伪造IN/OUT或写入原始事件表。
- 批准请假/缺勤从正常工作区间扣除；部分请假、休息交集、跨夜区间按精确时间处理，同一秒不得重复计入工作与请假。
- 额外工作以时间区间及归属日登记，员工申报或有权经理登记；保留原本人禁审和经理专审边界。批准后进入事实计算，不由录入者直接填写最终应付加班金额。
- 待审请假、撤销申请、额外工作和冲突都作为待处理项；不能因本日没有批准例外而忽略正在审批的事项。

## 5. 系统正常生效与异常核准

正常自动生效必须作为可审计的服务端行为，不能只是前端隐藏正常行，或GET查询时顺便写批准。

来源有效状态：未到期 / 待判定 / 系统有效 / 人工有效 / 待处理 / 来源已变。系统有效和人工有效属于考勤来源状态，不是工资已确认或已付款。

1. 服务端任务及显式“更新本月判定”命令使用同一评估器，分批处理到期来源。
2. 只有已结束、来源完整、无未决申请和未决异常的来源，才能生成系统有效记录。已批请假可直接带入，但冲突不能自动通过。
3. 正常算法和策略版本、来源指纹、模式、认定时间及来源快照保存；系统记录使用独立来源类型，不伪造某位经理审批。
4. 异常沿用人工核准权限、经理专审、本人禁审、版本和指纹检查。普通员工满足完整正常条件可系统生效；现有经理专审对象即使无异常仍由总部人工核准，不能为任务伪造总部身份。系统资格判定与依赖审核人身份的 `ApprovalReviewerPolicy.block` 分开：本人禁审约束人工写操作，不阻断员工查看本人系统判定。经理身份分类复用现有后端事实，不由前端声明。
5. 同一来源和算法版本重复运行不重复累计；源发生变化后旧记录失效，生成新判定或转待核对，人工豁免不能脱离旧来源偷偷复用。
6. 并发写遵循原 `payroll.source` 共享锁、日历/员工锁顺序；计薪捕获保持原独占协调。月度确认/重新判定不绕过这些锁。
7. 系统有效记录与人工有效记录由统一解析器供月表、工时汇总、readiness和工资读取，不能四处各写一套“正常”条件。

月底提供明确范围的汇总确认，不要求逐人打开正常日。确认绑定完整范围和来源指纹；分页、筛选不偷偷扩大或缩小确认范围。有权管理与有权发工资分别判断。未解决异常仍按适用规则阻断。

员工核对与反馈不额外增加“全员必须点确认”的工资前置门槛。核对有问题进入可追踪反馈，只有实际影响来源的事实变更才触发复核/重算。

## 6. 每日加班与月度薪资的一致性

复用 `PayCalculator` 的同公司同员工按日合并、日/周阈值和跨月周上下文，抽取可复用的逐日结果后由原工资引擎汇总；不在Vue计算 `下班－计划下班` 作为应付加班。

- 展示分别说明额外工作时长、暂计计薪加班和已确定计薪加班，缺合同/前序周数据时未知，不填0。
- 有前序日期待核准时，后续周阈值可能变化，该周受影响结果标暂计/待依据。
- 月初读取前月周上下文只消耗阈值，不重复支付；跨夜按原工作日归属，不因显示日历自然日而偷偷改工资归属。
- 带薪假与工作工时分开，不把带薪假加进加班阈值。
- 月表每日日结果之和须与同一来源版本的月度工资加班结果一致；门店筛选不能截断同公司跨店上下文。无权读取其他店明细时，只在有合法聚合权限的接口返回结果；无聚合权限则显示范围不足，不能泄露其他店工时或猜值。
- 公共假期/休息日待遇继续使用已有人工核对与适用合同政策，不能一律增加倍率。

## 7. 免打卡按合同计发

合同是结构化、版本化的有效个人计薪条款及其证据，不是上传PDF后任意解析文本即可自动发工资。复用现有个人方案、经济变更审批、生效与快照机制。

最低需要明确：计薪方式与单价、正常计薪单位来源、入离职折算规则、带薪/无薪假处理、加班待遇及适用项目。合同事实与政策选择有来源说明；缺失必要依据只暂停该员工受影响计算，不默认全额或零工资。

加班完全按合同：

| 条款 | 办理 |
| --- | --- |
| 明确包含于约定待遇 | 展示对应依据，不自动另算一次 |
| 明确另计 | 记录合同所需的有效单位/证据，按约定单价、倍率或固定项目办理，沿用金额审批；不强加打卡核准 |
| 明确不适用 | 按有效约定展示，不把“没填”解释为不适用 |
| 未约定/规则无法支持 | 显示条款待补或暂不支持，禁止猜算 |

合同约定不能用于绕过已有法定计算与支持边界；本设计不自行判断条款是否合法，也不新增法律规则。遇到需要适用性判定的情形沿用明确配置与核对要求。

当前 `fixed` 生成限定月薪且关闭自动加班，其自由员工全额规则不能直接作为新合同计薪实现。新合同计薪需独立生成口径，并扩展 `WorkModePayroll` 适配，避免将“非free＋fixed”当作唯一匹配规则。

## 8. 请假与个人假期政策

当前 `LeaveWrite` 要求 `scheduleId`，假别只有名称、带薪属性、启用及版本；尚无完整个人假期权益台账。为免打卡员工制造虚假排班以提交请假，不是可接受实现。

新增按员工、公司、时间区间的申请入口，排班关联可选。旧按排班申请保持兼容。审批、销假及审计继续复用；跨店申请按雇佣公司和任职范围统一避免重叠。请假净时长依据当时工作安排/合同假期单位规则，不能对所有人统一按8小时折天。

区分两层：

1. 月内请假统计和计薪影响：本次异常考勤的必要部分，覆盖有/无排班四类方式。
2. 个人额度、服务期累积、结转、到期和余额：独立权益台账能力。只有建立有效政策后才显示“剩余”，不能用“额度－当月请假”伪造全年余额。

权益台账采用批准扣减、待审占用、销假释放、独立更正的可追踪记录，员工与公司范围唯一计入；跨店不重复扣减。带薪资格与是否批准分开，余额不足如何处理由有效政策规定，不能自动变无薪或拒绝。

合同计发与自由员工可以有请假记录；是否改变工资分别由对应既有/新政策决定，不因记录假期就改变旧自由工资规则。

## 9. 模块与接口落点

| 所有者 | 职责 |
| --- | --- |
| 新 `attendancepolicy` | 四类方式解析、门店默认版本、员工覆盖、工作安排及来源快照；不处理定位或直接写金额 |
| 原 `workmode` | 定位、地址和旧自由策略；通过适配器协同新策略，不重写历史 |
| 原 `approval` ＋有效来源解析器 | 系统正常生效、异常人工核准、来源失效、月表/工资一致来源 |

| 原 `payroll` | 逐日加班投影、合同单位生成、工资确认守卫和金额治理 |
| 前端独立月表/单人月历组件 | 展示和操作，不能自行判定最终工时或工资 |

拟新增查询：`GET /api/v1/stores/{storeId}/workforce/attendance-month?month&employeeId&positionId&search&limit&offset`，按员工分页，每页返回该员工完整月内日期及合计；不要按排班分页后让前端拼出不完整员工月表。员工只读本人，不返回工资单价、金额、合同附件、地址或GPS。无排班但有有效任职的员工必须出现。

策略、工作安排、例外申请及系统判定命令在对应实施任务开始前另写完整API契约，包含DTO、权限、幂等、错误及精确安全白名单；本节为接口分工，不宣称已有可调用接口。

新持久化均带租户，门店/公司/员工归属使用可证明的约束与查询；使用追加版本与命令收据，保留创建人、时间和审计。原始打卡和非工资来源不回填、不删除；旧测试工资及其专用派生记录按清单清理，新版产生的确认快照正常保护。Flyway版本实施前检查，不能在方案里预占当前最后版本之后的编号；不删除或改写已执行迁移/Flyway历史来绕过升级。

### 9.1 工资来源证据直接采用新版模型

实施前 `PayrollDtos.SourceRef` 以 `scheduleId / approvalVersion` 定位来源，`SourceEvidence.actualSeconds` 是非空long；`PayrollLineage` 将其作为 `approved_work` 并直接使用scheduleId。新来源不能靠填空scheduleId或虚构排班硬塞进旧模型。

直接使用带版本的新版证据模型，区分排班人工核准、实打系统正常、按安排认定和合同计薪单位。来源有独立sourceId/sourceType、策略/安排/合同版本、系统认定或人工核准版本、指纹和必要快照；actualSeconds可空，不适用与0分清。合同单位来源只表达合同事实，不生成workSeconds充当出勤。

旧工资清理后不提供旧快照兼容解码或双模型回退；所有消费者直接按新版来源类型分派。工资明细lineage、项目source引用/批准验证、汇总、重算指纹和确认冻结一并改造，不只放宽 `APPROVAL_MISSING`。新版来源统一去重并检查变化。旧工资相关兼容分支、旧入口和过时测试可删除；可复用的计算器、法定规则、权限和审批能力按新版接口继续使用，不因“无需兼容”而重写正确计算。

### 9.2 线上与线下旧工资清理

清理对象限于经依赖核实的工资专用数据：旧模板/个人计薪配置及采用关系、岗位工资默认、工资批次/输入/计算/工资单与付款登记、工资变更申请及批准月版本、对应工资证据、年度工资事件与消费记录、补发及工资缴费结算测试台账、上述功能专用命令收据。法定费率政策、员工基础资料和原考勤事实保留。跨模块共享或归属不明确的对象不得直接纳入。

切换顺序为：新版本地验证 → 核对目标实例/数据库/schema及表行数/FK依赖 → 暂停旧工资写入和相关后台任务 → 同事务锁定并清理精确清单 → 核验员工等保留对象及其他产品未变 → 在实际授权的发布窗口切换新版 → 建立新版合成验收数据。线下可先在隔离合成库验证清理；线上清理只能在核实的RPB实例执行，不能引用其他项目连接。

不使用DROP整个schema、TRUNCATE CASCADE、关闭全库完整性约束或删除Flyway历史。实际清理事务遇到清单外依赖立即拒绝，回到依赖审计，不扩大删除。此处列的是已授权的切换工作，尚未执行的清理不得写成完成。

## 11. 实施顺序及完成标准

1. 策略与工作安排：四类方式可配置、可解释生效、旧员工不自动改制；先通过解析、权限、幂等、PG迁移测试。
2. 有效来源：正常自动生效、默认正常区间与例外；月表、readiness、汇总、计薪共用解析器；覆盖来源变化、并发及经理专审。
3. 无排班请假与合同计发：有/无排班请假可完成申请至销假；合同条款缺失明确阻断，不套用自由全额；经济变更继续治理。
4. 日加班与月表：共用计算、员工分页完整、异常优先、员工本人月历、管理员月表及汇总确认。
5. 权益台账：有效个人政策、占用/扣减/释放及余额，不能用当月统计代替；与前面请假链路衔接。
6. 合成数据链路与视觉验收：四类员工、两店、月初周、跨夜、合同变更、部分假、销假、入离职、工资重算、新版确认历史保护全部验证，再形成完成报告；旧工资清理与保留对象不变单独核验。

每阶段可独立验证，但四类方式、月表、合同/假期引用及薪资链路未贯通前，不将整项需求标记为已落地。未完成能力不开放成“可正常使用”的菜单或选项。

## 12. 必须覆盖的验收场景

- 四类员工同店并存；旧自由员工、旧legacy、定位方式及居家地址流程不回归。
- 默认变更、员工覆盖、解除覆盖、未来生效、跨店和月中变更不重写历史或默改工资。
- 正常留白与缺数据、未来、进行中、休息、不适用可区分；同日多例外不丢项。
- 正常自动判定重复运行、未知响应重放、并发来源改变不会重复或错误生效；GET不写入。
- 经理专审、本人禁审、门店权限、工资权限、跨租户及AppGate仍有效。
- 默认正常部分假、休息交集、额外工作、缺勤精确分段，无虚假打卡、无工作/请假重叠或双重扣款。
- 公司跨店/日周/跨月周加班和同一来源的工资结果一致；权限不足不泄露店外事实。
- 合同计发不要求打卡/工时核准；包含/另计/未约定明确，合同缺依据阻断，不擅自全额或零工资。

- 工资测算后来源变化要求重算；确认、发布、付款、提前结薪和补发沿用现有独立边界。
- 管理端与员工端中英文、320/390px及桌面、长姓名、多员工分页、空/错误/加载/无权状态验收。
