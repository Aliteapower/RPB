# 调休安排实现计划

用户已确认采用默认全选、允许取消个别员工的方案，继续本地实现，不提交部署。

设计：在考勤设置增加独立调休弹窗，选择已设置的店休/公共假期日期和补班日期、班次。每批最多500人，同店在职启用员工默认全选。预览逐人显示将取消的休息日排班和将新增的补班；已有关联打卡/有效请假/待补卡、补班日已有排班、跨店时间重叠、已参与调休日期均冲突跳过。未确认的源变化要求重新预览。

记录：新增V097调休明细，保留被取消排班ID、新补班ID和两日期。复用批量命令回执防重、ScheduleService的取消/新增与审计。公共假期标记与计薪逻辑独立，不扣减假期权益、不删除历史。

1. 先写PostgreSQL行为测试；明确原子取消+新增、冲突、无覆盖、重试、源变化、审计回滚及门店权限。
2. 新建scheduling/restswap的DTO、repository、plan/service和窄API。共用现有员工、班次、门店、AppGate及source/planning/calendar/employee锁。只追加迁移。
3. 独立RestSwapDialog及双语文案，考勤设置提供入口；预览后显式确认取消/新增数，失败重试沿用同一命令ID。
4. Board与CalendarPage附加独立restSwaps元数据（旧构造器兼容），不把人员调休混入核准公共日历源。周/月格子、列表及员工日历显示关联日期，员工仅见本人。
5. 执行必要测试、构建、独立审查；按本地数据库指针使用已有专用验收schema，核对原始数据不变，浏览器验证并记录发布说明。暂不部署。
