# 统一扫码设备设置与扫码枪兼容开发方案

> 执行方式：按 writing-plans / executing-plans 在当前会话逐项实施。用户已授权先写方案再开发，不增加审批节点；不提交、不推送、不部署。保留 D:/RPB 已有改动。

**Goal:** 员工使用同一个扫码入口，按本机、租户和门店设置使用相机或 HID 扫码枪，兼容顾客个人码、卡核销码、取酒码和瓶身商品条码。

**Architecture:** 共享商务模块负责设备偏好、设置和扫码枪输入。员工扫码适配组件选择输入源，继续使用现有 QR/GTIN 校验；业务组件负责完成、继续接收和未决暂停。顾客手机端扫描商户码仍使用原相机组件，不读取员工设备设置。

**Tech Stack:** Vue 3、TypeScript、localStorage、现有 Vue 自定义 renderer / node:test；不新增依赖、API、权限、数据库迁移。

**Spec:** 本文包含本次最终设计与实现步骤，以用户本次讨论和“各业务入口复用原有规则”为依据。

**后续授权与发布：** 用户在开发完成后明确要求“提交部署”，已据此将功能提交`85d86bd8`发布到RPB生产前端。初始“不提交/不部署”仅记录当时开发阶段边界；当前发布结果见[生产发布记录](../../development/SCAN_DEVICE_PRODUCTION_RELEASE_20261104.md)。

## 浏览器范围补充（2026-11-04）

用户确认本期先支持 Windows 桌面版 Google Chrome 和 Microsoft Edge，目标为当前稳定版。共享输入继续采用标准文本输入、Enter、焦点及页面可见性事件；不添加浏览器品牌判断或要求安装网页扩展。

目前没有实体扫码枪，先通过键盘逐字符输入/粘贴后 Enter，验证码校验、连续接收、处理中锁定、失焦恢复及业务分流。自动化模拟测试与浏览器实际测试分别记录；只有设备到位后才验收 HID 输出、后缀、键盘布局和实物/手机屏幕识读。缺少扫码枪不阻止前端开发和软件流程验证。

Chrome、Edge 的实际浏览器验收均待执行：当前浏览器工具仍返回 Work 设置禁用本地浏览器，不能把 renderer 测试标为这两个浏览器已通过。浏览器访问恢复后分别验证，使用隔离测试数据，不执行真实顾客扣款/核销。

## 最终设计与边界

1. 一个扫码入口，不增加日常模式切换。设置提供相机（默认）/扫码枪，两者按浏览器 origin + tenantId + storeId 保存；只保存设备方式，不保存码或顾客资料。无有效员工作用域则默认相机，不读取其他作用域。存储不可用时本次会话仍可使用，明确未持久保存。
2. 钱包、存酒设置复用同一个设备设置组件；统一扫码页提供折叠的本机设置，方便仅有扫码权限的员工。偏好不授予权限、不修改租户业务设置。
3. HID 键盘模式扫码枪输入到专用文本框，以 Enter 结束；保留识别按钮。不开相机、不请求 USB/串口权限、不在整页截获键盘。页面需前台且接收框有焦点；失焦提示恢复接收，编辑金额/备注不抢焦点。处理中丢弃残留，不排队，不以输入速度猜测完整码。
4. 员工钱包扫码、统一扫码、卡业务、取酒和商品维护/商户存酒选品复用设置。顾客扫描商户码、顾客提交存酒申请等公共页面保持原流程。
5. 扫码枪统一扫码页：卡/取酒明确 completed 后保留结果并自动等待下一张；未知或非完成结果暂停。请求处理中锁定。已成功的同一授权码在本次会话不重复提交，服务端幂等继续生效。只读识别/明确拒绝后可继续；未决事务保留现有恢复入口及原员工限制。
6. 个人码未开始办理时允许下一张替换；选定消费或跳转具体业务后不能覆盖当前草稿。各业务保持原确认/金额/交易结果页，完成后清除顾客；扫码枪的身份入口在空状态自动准备接收，避免再点“扫下一位”。不自动跳过待顾客确认账单或未决交易，也不将识别身份视为付款授权。
7. 商品条码走现有 GTIN 校验，保留前导零及原样条码，不接受顾客码。商品维护只填入条码，继续按原规则保存。商户直接存酒提供瓶身扫码选品：每次成功扫描一瓶，同商品重复扫描可增加数量，只改待确认清单，不自动登记库存。只能匹配本店可用的唯一酒品，未找到/冲突不自动建商品。已开瓶/数量上限/多个存放条件不自动合并；顾客申请收存不以扫描擅改申请数量。
8. 近期结果仅会话内保留有限条数，展示业务类别/数量/状态，不保存原始码。切租户、门店、账号及离页时清理扫码草稿和结果；迟到响应不得更新新作用域。
9. 相机行为回归不变；设备必须支持需要的一维/二维制式及手机屏幕读取，软件模拟输入不等于实体扫码枪验收。

## 方案取舍

- 采用统一设备偏好 + 输入适配组件：用户已选择，业务接口与权限保持原属模块。
- 不采用两个日常入口或页内模式切换：增加操作步骤。
- 不采用全页键盘监听、自动排队交易或静默串口访问：会干扰表单或造成误办理。

## Global Constraints

- 不改后端、API、权限、订阅、迁移、依赖、运行配置，不使用真实顾客交易验收。
- 不覆盖现有未提交文件；本次触及文件先核对其已有改动。
- 复用模块容器、面板和按钮；验证受影响页面及相邻页面，未实际完成的浏览器/硬件验收明确列出。
- 需要本地后端或 SQL 时先读 `target/local-postgres-current.txt`；不回退其他数据库。

## Review Focus

- 失焦、后台、按住 Enter、CRLF、多次回车和处理中输入不产生重复/排队命令。
- 切租户/账号/门店、权限失效后的迟到响应不污染新页面。
- 交易未知结果不能因连续扫码绕过原恢复及幂等流程。
- 商品同码多次扫描是多瓶；顾客授权同码重扫不能重复交易，两者规则分离。
- 未匹配、多个匹配、开瓶、上限、已有手工调整条件不得静默合并或新增商品。
