# 第三阶段：薪资批量采集与事务外计算

用户授权：本地实现及验证，不提交、推送或部署。承接长期个人方案及四类考勤，业务规则不变。

## 模块和执行边界

1. 来源层批量读取员工、成员门店、雇佣区间、方案、凭证、排班、最新核准、考勤、请假、日历及考勤方式。保留原排序、来源指纹 JSON 结构、500 人/10000 排班限制。
2. 编排层通过独立事务工具捕获可重复读快照，事务结束后执行纯计算。计算线程不访问数据库或权限上下文。
3. 提交层短事务依次获取批次锁、核验版本和权限、获取现有租户来源锁、再次批量采集并比较完整指纹；来源变化返回既有 `WORKFORCE_PAYROLL_SOURCE_CHANGED`，版本变化返回既有冲突。保留来源写入共享锁。
4. 创建自动草稿同样先捕获和计算，再原子插入及审计。失败不留下半成品。确认仅核验计算，保留原始工资快照和计算时间；发布、作废不改金额。
5. 有限计算池最多 4 个工作线程、最多 2 个在途批次、有限任务队列；按原员工顺序汇总和舍入。饱和返回 `WORKFORCE_PAYROLL_BUSY` / 503，可重试，不产生写入。命令成功重放保持原响应。
6. detail/list 保留 REQUIRED 查询事务，避免付款服务在同一事务内读取不到刚登记付款。

## API 兼容核对

路径、请求、响应及权限模型不变。计算/确认期间允许其他请求改变来源或输入，最终校验失败需重新计算；不自动确认过期结果。新增 503 忙碌错误不记录成功回执，客户端保留命令供重试。已成功命令仍先重放，再判断版本。无数据库迁移、无新后台基础设施。
