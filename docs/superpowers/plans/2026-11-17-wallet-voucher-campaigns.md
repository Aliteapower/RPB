# 储值钱包抢券活动实施计划

依据本聊天确认的最终方案，在持卡与核销工作台交付免费代金券和产品券。

- 数据层新增活动、规则版本、领取记录。活动锁串行化编辑、启停及发券，活动内浏览器领取凭证唯一，来源 IP 仅用于审计。单券锁串行化核销。
- 管理接口使用 /api/v1/stores/{storeId}/wallet/cards/voucher-campaigns，按现有卡业务门店和权限边界检查。GET 列表，POST 新增，PUT 更新，POST 状态切换，DELETE 删除未领取活动。
- 公开接口使用 /api/v1/public/voucher-campaigns/{id}，GET 查看，POST /claims 领取。浏览器凭独立随机凭证恢复，公开请求不读取认证会话。领取结果区分成功、已领取、活动状态和领完。
- POST /api/v1/stores/{storeId}/wallet/cards/vouchers/redeem，仅租户管理员在适用门店操作。服务端返回核销成功、已使用、未生效或已过期。
- 工作台复用卡方案布局，独立活动编辑器。公开页生成券码及可下载图片，现有扫码台识别新类型。
- 本地 PostgreSQL 测试先覆盖最后一张、同 IP、复扫、产品券快照，再执行前端构建和回归测试。保留生产状态。

## 接口与运行边界

- 管理列表返回活动状态、时间和三个计数，详情返回当前券面。更新、切换状态和删除携带活动版本，遇到旧版本返回 409。已发放券依据发行时的券面版本核销，活动归档保留记录。
- 匿名查看及领取可携带 X-Voucher-Receipt，值为当前浏览器生成并保存的随机 UUID。重复提交同一凭证恢复原券，同 IP 的不同浏览器凭证可独立领取。公开返回内容禁止缓存。
- 核销码使用 VC. 前缀，扫码台仅将格式符合的凭证提交本租户门店接口。未登录返回 401，权限和非适用门店返回 403，不存在及跨租户的券码返回 404。已使用和过期属于正常扫码结果。
- 客户端连接地址以服务端收到的 TCP 对端为准。未来通过反向代理开放时，用 rpb.vouchers.trusted-proxies 显式配置受信任的代理地址。代理须覆盖 X-Real-IP，确保来自客户端的同名头不会传到后端。本地直连无需配置。
- 新迁移 V137 预留在主工作区已有 V129–V136 之后。管理员操作沿用储值钱包 App Gate，发券还检查活动所属门店的储值钱包及卡功能状态。

## 分享与核销提示

公开分享二维码编码活动链接。管理端和公开页分享同一活动地址，领取凭证和单张券的核销码不参与分享。
扫码响应增加 batchCode 和 redeemedAt。batchCode 取四位活动代码。成功和复扫返回首次核销时间，未生效和过期返回空时间。现有核销事务和状态码保持原规则。
- 分享入口默认使用 RPB 公共入口域名。本地手机验收可用 VITE_VOUCHER_PUBLIC_ORIGIN 指向局域网测试入口。浏览器支持系统分享时可直接转发，也可复制链接或下载二维码。
- 领取和扫码结果使用可关闭的单弹窗。首次打开已领完或已结束的活动也弹出对应提示。复扫显示原始批次号和活动时区的首次核销时间，精确到秒。

## 发行总量和核销序号

扫码响应增加 issueTotal 和 redemptionNumber。首次核销在同一事务递增活动核销计数，并将结果及当时发行总量写入单券记录。复扫读取原记录。V138 用历史核销时间为已核销券补序号，时间相同按券码哈希固定排序，历史总量使用迁移时的活动发行总量。

## 再次扫描活动链接

公开活动 GET 和领取 POST 使用同一来源 IP 解析。已持有领取凭证的浏览器可恢复原券，重复打开弹窗提示「你已领取1张，成功走起！」。同 IP 的其他浏览器按当前活动库存独立领取，不能读取原券码。

## 活动券统计

GET /api/v1/stores/{storeId}/wallet/cards/voucher-campaign-report 支持 query（活动名称或四位批次号）、kind（cash/product）和 page（从 0 开始）。返回每页 20 个归属当前门店的活动及 hasNext。权限沿用活动管理读取权限，停用卡功能时仍可查询历史。发行总量取当前活动配置，已领取和已核销取活动计数，过期按已领取的各券规则版本和时区统计未核销券。

## 核销登记号与分享批号

登记号由四位活动批号、首次核销时的发行总量和点号后的核销序号拼接。批号 4723、发行 10 张、第 1 张核销显示 472310.1。原批号、发行量、核销序号和时间仍独立展示。匿名活动响应包含四位批号，分享弹窗及下载的二维码图片显示批号，二维码内容仍是原活动地址。

## 品牌券图与打印海报

复用租户资料 Logo，通过活动随机 ID 提供 GET /presentation 和 GET /logo，只返回该活动租户当前公开品牌资料。presentation 含 face、batchCode、tenantName、logoUrl、startsAt、endsAt。logo 仅解析当前租户 Logo，不接受任意媒体 ID。
券面、导出图片及海报统一采用深蓝细纹理头部，右上角租户 Logo。保存券图生成 PNG 预览，支持长按存图和系统分享图片。海报默认 A4 竖版，内容自动排版，规则长文续页，二维码编码原活动公开地址。海报支持打印和保存图片。本轮本地验证。
门店信息使用已有 share_address、share_contact_phone，按活动适用门店和租户边界读取，券面、图片和打印海报共用。系统资料未填写的字段不生成虚构内容。
本地验证：15 项后端测试、60 项相关前端测试通过，生产构建通过。真实浏览器验证 390px 券面、测试租户 Logo 上传及显示、PNG 下载与二维码解码、原活动海报二维码、地址电话、系统图片分享接口（模拟），并渲染 A4 打印 PDF，普通内容 1 页、长规则 2 页且末尾内容完整。手机相册实际保存与实体打印待实机验证。本轮未发布。

## 同一手机浏览器限领（2026-11-18）

GET 和 POST 保留现有 X-Voucher-Receipt 契约，POST 仍必须提供合法 UUID。同一浏览器按活动在 localStorage 保存凭证，打开活动即初始化，领取前再次读取以复用其他标签页已保存的凭证，旧凭证继续有效。重复请求和换网恢复原券，不重复增加领取计数；不同活动独立。来源 IP 保留审计但不参与限领。V139 将主键从 campaign_id + ip 切换为 campaign_id + receipt_hash，替换原有同字段唯一约束，不删除历史领取及核销记录。库存活动锁和核销事务不变。浏览器标识不是硬件身份，切换浏览器、无痕或清除数据可重新领取；本轮按宽松匿名领取要求接受此边界，不增加登录或手机号验证。

验证清单：同 IP 不同凭证分别领券；同凭证换 IP、并发重试仅发一张；同凭证可参加另一活动；同 IP 并发抢最后一张不超发；核销与复扫计数保持；迁移保留旧券。仅本地验证，未授权发布。

本轮验证完成：16 项后端测试、61 项前端测试和构建通过。本地 Flyway 从 V138 升级至 V139，迁移前后已有领取记录整行聚合校验一致。真实 Edge 浏览器三个独立 390px 会话从同一来源 IP 并发各领取一张，后台为 1 个 IP、3 条领取；同会话新标签页复用凭证、8 次并发重试不增发，第四会话领完仅单弹窗；核销及复扫后 issued=3、redeemed=1，首次序号和时间保持。手机硬件实机尚未复测。本轮未提交、未发布。

发布说明（2026-11-18，本地待发布）：改变匿名限领维度；API 路径、头字段、权限、租户门店边界及其他产品线保持兼容。V139 只调整领取表约束。回退应用版本可保留 V139 表结构；放宽后同 IP 已可能存在多条合法券，不能直接恢复旧 IP 主键，也不得删券来强行回退。恢复旧数据库结构须使用发布前完整恢复点并评估期间新记录，实际发布前按项目备份与发布流程执行。

## 新活动规则种子（2026-11-18）

新建代金券和产品券活动的规则输入框预填以下五条，可不修改直接保存，也可编辑保存。仅作用于新建活动，编辑已有活动保留原文（包括租户主动清空的规则），不会用种子覆盖。

1，此券不兑现，不找零。
2，每张代金券可到店使用一次。
3，请向店员出示核销二维码。
4，不与其他活动同享。
5，活动最终解释权在规定范围内归本店所有。

本轮验证：本地 Edge 挂载真实活动编辑组件并连接本地后端，确认新建默认五条原样保存持久化、修改后保存并重开保留、主动清空后不回填、新建产品券同样预填；前端类型检查及构建通过。无新增接口或数据库变更，未提交、未发布。
