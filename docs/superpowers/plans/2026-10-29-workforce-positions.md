# 岗位目录 Implementation Plan

**Goal:** 管理员维护租户岗位目录，员工资料选择岗位，保留旧资料和冻结工资。
**Architecture:** workforce 内新增 positions DTO/repository/service/controller；租户拥有岗位，沿用AppGate及总部管理员维护权限，员工管理员可读取选项。员工增加可空positionId，jobTitle保留展示和旧API兼容。无岗位可不设置；停用岗位仅允许原员工保留，未引用岗位软删除；被引用禁止删除。改名后员工当前资料显示新名，历史审计/工资快照不改。
**Tech Stack:** 既有Java/Spring、PostgreSQL/Flyway、Vue/TypeScript。

- [x] 保存基线与岗位/API/迁移契约；先写真实PG测试。
- [x] V092迁入去空白去重旧岗位并关联员工；同租户复合FK、有效名称唯一、索引与生命周期约束。
- [x] 岗位维护及员工选择校验，版本锁、重试/并发、审计原子性；兼容旧jobTitle调用但禁止创建任意未维护值。
- [x] 岗位管理页面、员工下拉、中英文及空/错误/权限状态。
- [x] PG/API/前端回归，指针数据库独立升级验收schema，重建并重启8096/5196本地页面，保留全部工资和测试资料。
- [x] 审查、文档与发布记录；不提交、推送或部署。

用户随后纠正导航：“不是在管理员，是管理页面增加岗位管理，让管理员可以维护岗位管理”。已保留岗位功能及权限，移除管理员授权页内的岗位子导航；新增独立workforce/management页，顶部“管理”进入后，岗位管理与管理员授权并列。已异步询问是否指租户后台，目前按当前员工考勤模块落实，未扩大至其他产品。

测试清单：增改启停删除；重复名称、过期版本、重放；引用保护；停用保留/新分配拒绝；未知岗位/跨租户拒绝；经理可选择不可维护；AppGate拒绝；迁移回填和冻结金额不变；审计失败回滚。
