# 钱包产品线实现计划

> 按 `superpowers:executing-plans` 在当前会话逐项执行，结合 TDD、API Review、Database Review 和最终 Code Review。用户已授权实现，不新增审批节点，不提交、推送或发布。

**目标：** 实现复用统一资料及平台计费的线下储值钱包，包含三渠道充值、顾客确认、双向扫码、部分支付、退款和到期善后。

**架构：** 新增 `wallet` 原生模块，按账户/资金账本、充值、结算、消费授权、退款划分应用用例与持久化文件。通过公共查询端口复用顾客/组织/资料，通过 PayNow 适配复用码生成；平台计费负责订阅，钱包不拥有订阅状态。

**技术：** Java 21、Spring Boot、JdbcTemplate、PostgreSQL/Flyway、Vue 3/TypeScript、既有 qrcode。

**规格：** [钱包产品线开发需求](../../development/钱包产品线开发需求.md)。

## 全局约束

- 保留原有未提交文档和 `rpb信息.txt`，不读写真实生产数据。
- 不接线上支付，不复用 OCR 自动确认作为充值依据。
- 金额为 SGD 定点数，禁止透支；资金记录只追加，数据库约束、事务和幂等同时兜底。
- 统一租户/经营主体/门店/顾客/认证来源；顾客只操作本人，员工逐店逐动作授权。
- 所有真实 PostgreSQL 验证使用本工作区 `target/local-postgres-current.txt`，独立测试 schema。
- 仅钱包所需的计费增强及公共安全挂接，不修复无关产品缺口。

## 审查重点

1. 多设备同时确认/支付/补差：只提交一次且不透支，数据库并发测试证明。
2. 收款已发生而软件失败：保留可恢复事实，重试同一单，不让顾客再付。
3. 顾客码不能变成员工无限额扣款凭据：绑定、本人确认、金额/版本/期限、一次性使用。
4. 到期后只允许受控原单善后和本人查询，不能借善后创建新交易。
5. 退款不重新生成原账单应付；保留原渠道、累计可退和钱包冻结限额。

## 文件与接口边界

- `wallet/domain`：金额/状态规则、显式数据记录与错误。
- `wallet/application`：`WalletAccess`、`WalletAccountService`、`WalletTopupService`、`WalletCheckoutService`、`WalletAuthorizationService`、`WalletRefundService`、查询与窄适配端口。
- `wallet/persistence`：按计划/账户/账本、充值、账单、授权、退款、幂等/审计划分 Repository。
- `wallet/api`：员工、顾客两个认证边界，显式 DTO、错误映射及同源验证。
- `payment/application`：窄 PayNow 码适配，不改变 quick-pay 或截图确认行为。
- `platformbilling`：显式选择门店的购买/续费契约，历史其他产品调用兼容。
- `src/modules/wallet`：客户端类型/API、员工收银、顾客钱包、设置/对账、QR 扫描与显示组件。
- `V057__wallet_product_line.sql`：产品目录、未定价模板、职责权限、资金业务表及约束；不自动开通租户。
