# 常用入口系统化修复

## 目标与设计

新租户、新门店和新产品的分享入口不依赖临时新增子域的 DNS/TLS 配置。所有分享链接及二维码使用当前部署配置的主域，保留门店 ID；受保护入口使用现有登录类别、tenantCode 和内部 redirect。原租户子域登录机制不变。

选择统一主域而非仅补 mw 单个证书或在页面等待证书：前者覆盖以后所有新租户，已有门店路径及后端范围校验可直接复用，不新增基础设施依赖。旧二维码里的租户子域不能靠修改前端内容修复，需要单独获准配置生产证书。

复用产品注册目录，将额外的顾客和管理入口声明放入同一目录。普通员工产品入口默认使用既有 value；新增产品不复制产品白名单。保持产品开通/到期、门店启用、身份和权限的现有后端判断。主域共用登录存储，受保护链接可能需要重新登录到目标租户，不能替换当前会话或扩大权限。

## 实施顺序

1. 在 tenant-entry-links 测试先重现新租户子域问题，覆盖主域、平台域、其他租户域、本地、端口、不可信来源和受保护跳转。
2. hostContext 增加统一分享 origin 的纯函数，常用入口和预约分享复用；仅使用配置的受信主域，在无配置环境不猜新域。
3. product-line-entries.json 追加可选 distribution 元数据；Java 注册记录兼容加载，前端从目录生成额外角色入口。测试所有现有路由与未来新产品默认入口。
4. useTenantEntries 接入 useVisiblePageRefresh：30 秒、focus/pageshow/恢复可见刷新，no-store，同范围不重叠，切店/卸载丢弃旧响应，失败清除可分发入口。
5. 运行关联 Node 行为测试、Java 注册/入口权限测试、类型检查和构建，审查范围并补 API 文档及发布说明。

## 验证与边界

- 使用合成响应/已有测试夹具验证开通、到期、恢复、切店竞态、权限拒绝和外租户响应拒绝。
- 校验各产品分享路径可被真实前端路由解析，登录 redirect 是内部本店路径。
- 不新增 API、迁移、权限或真实订阅写入；不修改工作区原有无关改动，不自动提交/推送/发布。
- 运行环境验证前读当前工作区 target/local-postgres-current.txt；生产只能只读核查，无实体扫码或印刷验收则明确报告。
