# 双端紧凑取酒车

用户已确认：顾客提交整车生成一个批量取酒码，店员核销后扣库存；商户员工一次提交直接批量交付。不新增二次勾选或确认页，取酒车就是最终提交清单。

- 复用现有存酒页面容器、照片权限、放大组件和数量样式；商品行左缩略图、右酒名/余量/加减，下方位置、标签和到期说明。无照片显示中性图标，不假造商品图片。
- 共享PickupCart只管理本次内存中的数量和列表/取酒车视图；0表示未加入，最多50款。切门店/顾客或成功提交清空；刷新库存不静默改数量，失效、过期、超量必须调整后再提交。不把顾客资料写入本地缓存。
- 顾客使用原POST /intents提交selections，展示一个整车二维码和明细，继续原取消、过期和核销链；不会直接扣库存。
- 商户使用原POST /direct-deliver提交customerId及selections，不再弹第二个确认区；车内清楚提示提交即登记实物交付、扣减库存。保留原权限、未确定操作恢复、幂等和整批原子库存校验。
- 先补购物车模型与角色批量行为测试，再更新旧单瓶UI测试，验证刷新、范围切换、库存冲突、重复点击、原单取消与照片。用指针数据库验证现有批量服务；干净源码构建、桌面/窄屏浏览器验收后按本聊天既有授权发布。
